# Repository Audit: cricut-lite (Open Design Space)

Date: 2026-10-12. Code baseline: `main` at `0d3903f` ("Merge spec 18"). Docs-only commits up to `c346892` ("Spec 21 design review") are included; they change no code, so every `src/` line reference below holds at both commits.

## 1. Executive Summary

**What it is.** Open Design Space is a single-binary Rust 2024 desktop app (egui/eframe 0.31, about 24k lines in 81 files) that clones the Cricut Design Space canvas and its Make flow, driven by a simulated machine. Specs 00 to 20 were built by parallel agents and merged; spec 21 (live effects) is in design.

**Condition.** The model layer is in good shape: `containers`, `path_edit`, `links`, `text` and `composition` are pure, well named and well tested, and the build and default clippy are clean. The weaknesses sit at three edges: persistence (work can be lost without warning), input boundaries (malformed SVG or project data can crash the app), and the UI layer, where each spec added its own dispatch path and enable rules for shared edits, and those surfaces now disagree.

**Strengths to keep.** Whole-frame snapshot undo, the idempotent `settle` with load-time repair, `path_edit`'s model-owned `check`/`apply` command API, the pure Make flow and device reducer, per-test temp project directories, and `#[serde(default)]` fields with back-compat load tests.

**Most important risks.** Unsaved work is discarded with no prompt and failed saves are silent (AUDIT-001, AUDIT-002); unbounded curve flattening crashes on large or non-finite input (AUDIT-003); committed Cricut icon artwork and thumbnails block any open-source release (AUDIT-004); and the absence of one edit-command model (AUDIT-005) is already producing behavioural bugs.

**Highest-leverage moves.** Spec 22 should fix persistence, input bounds, licensing, the test flake and CI together. Spec 23 should introduce one `Edit` command model before spec 21 adds more operations to every surface.

## 3. Repository Map

* **Application.** One binary crate, `cricut-lite`. `main.rs` builds an eframe app (`ui::CricutLite`).
* **Model (pure, no UI state).**
  * `design.rs` holds `Design`, `Shape`, `History` and SVG export.
  * `Design` is extended by feature in `links.rs`, `containers.rs` (tree, `settle`, auto layout), `flatten.rs`, `text_ops.rs`, `warp.rs` and `path_edit.rs`.
  * Supporting modules: `geometry.rs`, `transform.rs`, `snap.rs`, `units.rs`, `text.rs` and `pens.rs`.
* **Make side.**
  * `composition.rs` packs shapes onto mats.
  * `make_flow.rs` is a pure state machine with an outbox.
  * `bridge.rs` builds the wire payload.
  * `device.rs` runs the simulated machine on a thread over `mpsc` channels.
  * `proto_enum.rs` declares the wire enums.
* **UI (`src/ui/`).**
  * `mod.rs` holds the app shell, frame loop and persistence glue.
  * Surface modules: `canvas`, `chrome` (top bar and menus), `toolbar/*`, `selection` (action bar), `context_menu`, `layers_panel`, `layers_actions`, `inspector`, `home` and the Make flow screens.
  * Kittests sit in `ui/mod.rs`'s `tests` module plus 15 `tests_specNN.rs` files.
* **Data stores.**
  * Projects are JSON files with PNG thumbnails, in the OS app-data directory or `ODS_PROJECTS_DIR` (`project.rs`).
  * Settings live in `settings.json` (`settings.rs`).
* **External services.** None. System fonts are scanned once per process on a background thread (`system_fonts.rs`).
* **Runtime flow.** Each editor frame runs these steps:
  1. Clone the design.
  2. Let surfaces mutate it.
  3. Run `settle` once.
  4. Run `History::observe`, which folds the frame into at most one undo step.
* **Build.** Cargo only, with `Cargo.lock` committed. There is no CI, toolchain pin or release packaging.

## 6. Detailed Findings

### AUDIT-001: Unsaved work is discarded without confirmation

**Severity:** High
**Category:** Data integrity
**Confidence:** Confirmed (code). The window-close path is traced, not run.
**Scope:** Systemic
**Sources:** A-01. Related: AUDIT-002.

**Locations**
* `src/ui/mod.rs:211-219` `open_design`: replaces the design and sets `self.history = History::default()`
* `src/ui/mod.rs:169-180` Home New, Edit and Make all call `open_design`
* `src/ui/mod.rs:301` `C::New => self.open_design(Design::default(), None)`
* No `on_exit`, close-request handling or dirty flag anywhere in `src/`

**Finding**

The app does not know whether the canvas differs from its saved project. File > New, opening another project from Home, Make from Home and quitting all replace or drop the current design without asking. `open_design` also resets history, so Undo cannot bring the work back. The only confirm dialogs (`home::Confirm`) guard Delete and Clear All.

**Why it matters**

One click on New after an hour of unsaved work loses that work for good. Save is manual and there is no autosave.

**Kept separate from AUDIT-002.** Both findings are about data integrity, but they have different fixes. This one needs dirty tracking and a confirm-before-discard flow at four transitions. AUDIT-002 needs a correct, atomic, reported save. Either can ship without the other, and each needs its own tests. They should land in the same spec (22).

**Recommendation**

1. Keep the last saved design (or its hash) beside `project`, and derive `dirty = design != saved`.
2. Route New, Home Edit, Home Make and the viewport close request through one `confirm_discard` step, reusing the `home::Confirm` dialog. The step offers Save, Discard and Cancel.
3. Show the dirty state in the title.

**Validation**

* A kittest edits the canvas, chooses New, and asserts that a dialog appears and that Cancel keeps the shapes.
* The same test runs for Home Edit and for a close request.

### AUDIT-002: Failed saves are silent and fork the project; writes are not atomic; unreadable projects vanish

**Severity:** High
**Category:** Data integrity / Operability
**Confidence:** Confirmed (code). Not reproduced with a real I/O error.
**Scope:** Systemic
**Sources:** C-02, D-03, A-04. Severity: C rated this High; A and D rated it Medium. It is kept at High because the user is told nothing and the realistic outcome is lost or duplicated work.

**Locations**
* `src/ui/mod.rs:286-295` `save_to_disk`
* `src/project.rs:72-80` `save`, `:82-85` `load`, `:108-119` `list`, `:53` `projects_dir`
* `src/ui/mod.rs:169-180` Home Edit and Make ignore `load` errors
* `eprintln!` as the only error reporting: `src/ui/mod.rs:183, 192, 281, 341` and settings save

**Finding**

1. **Identity loss.** `save_to_disk` calls `self.project.take()` and restores the project only if `project::save(..).is_ok()`. Any error leaves `self.project = None`, and nothing is reported. That includes a thumbnail write that fails after the JSON succeeded. The next Save mints a new id through `Project::new`, so the work forks into a second project and the stale original stays on Home.
2. **Torn writes.** `std::fs::write` truncates the file and then writes it. A crash or a full disk mid-write leaves invalid JSON.
3. **Silent disappearance.** `list` uses `filter_map(.. .ok())`, so a torn, hand-edited or newer-format project disappears from Home. `clear_all` builds on `list`, so it never deletes those files either. Edit or Make on an unloadable card does nothing visible.
4. **Invisible errors.** If `projects_dir()` cannot be created, Save does nothing. Every other error goes to stderr, which a Finder launch never shows. README:69 promises "Save / Saving... / Saved" feedback, but no such string exists in `src/`.

**Why it matters**

The user can press Save, see nothing wrong, quit, and lose the work. Disk-full and permission errors are realistic causes. Projects are the app's only persistent user data.

**Recommendation**

* Clone the project rather than `take()` it, and reassign it only on success. Return the `io::Result` and show it in the top bar or a toast. Make that one app-level error channel, and replace the `eprintln!` calls with it.
* Write to `<id>.json.tmp`, then `rename` over the target.
* Treat the thumbnail as best effort, so a thumbnail failure never fails the save.
* Have `list` return unreadable files alongside the readable ones, so that Home shows a "could not open" card.
* Add a `format` version to `Project`, so that a newer file is refused with a message rather than hidden. Spec 21's review raises the same need ("No format version").

**Validation**

* A unit test saves into a read-only directory and asserts that the project keeps its id and an error is surfaced.
* A test writes a truncated JSON file and asserts that `list` reports it as unreadable.

### AUDIT-003: Unbounded curve flattening crashes or freezes on large or non-finite input

**Severity:** High
**Category:** Robustness
**Confidence:** Confirmed for the mechanism, using a probe copy of `flatten_cubic` and the locked `usvg 0.37.0`. High confidence for the in-app crash, which was not run.
**Scope:** Systemic
**Sources:** D-01

**Locations**
* `src/geometry.rs:37-50` `flatten_cubic`: recursive, with no depth cap, point cap or finiteness check
* `src/shape_library.rs:113-171` `import_svg`: no bound on coordinates, segment count or path count
* `src/design.rs:795-803` `add_imported`: floors size at 0.01 in, with no ceiling. The inspector clamps to `CANVAS_IN` (`src/ui/inspector.rs:71`)
* `src/project.rs:82-85`, `:108-119`: plain `serde_json::from_str`, with no validation of `Design` values

**Finding**

`flatten_cubic` subdivides until both control points lie within tolerance of the chord. The probe gave these results for a span s:

| Span s (in) | Result |
|:---|:---|
| 1e4 | about 1.5k points |
| 1e6 | about 1.3M points |
| 1e8 | about 13.5M points |
| 1e10, or inf or NaN | never terminates: f32 midpoints stop converging, and `NaN <= tol` is false |

The never-terminating cases overflow the stack, and Rust aborts the process. `usvg` accepts a path 1e12 px wide, and `import_svg` turns it into a shape of that size. Project JSON can carry the same values, because serde reads an out-of-range f32 as infinity.

**Why it matters**

A malformed SVG, such as a CAD export with absurd units, kills the app and takes unsaved work with it (compounding AUDIT-001). A project saved with such a shape can never be reopened.

**Recommendation**

1. Make `flatten_cubic` total. Pass a depth, stop at about 16 levels, and treat a non-finite input as a straight segment to `p3`.
2. Validate at both boundaries:
   * `import_svg` rejects non-finite bounds, or scales the import to fit `CANVAS_IN`.
   * A `Design::sanitise` runs in `project::load` and `list`. It rejects non-finite numbers and clamps sizes to the inspector's range. `settle`'s load-time repair is the model for this.

**Validation**

* Unit tests flatten a NaN cubic and a 1e10 in cubic and assert a bounded point count.
* An `import_svg` test with a 1e12 px path asserts `Err`, or a size of at most `CANVAS_IN`.
* A `load` test with `"width_in": 1e39` asserts the value is rejected or clamped.

### AUDIT-004: Cricut artwork is compiled in and committed

**Severity:** High
**Category:** Licensing / supply chain
**Confidence:** Confirmed for provenance, which the repository's own notes document. The legal conclusion needs someone qualified.
**Scope:** Systemic
**Sources:** C-01. The missing LICENSE file is covered in AUDIT-012.

**Locations**
* `assets/ds/icons/*.svg` (116 files). Of these, 22 are compiled in through `include_bytes!` in `src/ui/icons.rs:79` and the `svg!` table from `:87`.
* `assets/ds/shapes/previews/*.png` (20 files, unreferenced by code).
* `docs/specs/reference/*.png` (Design Space screenshots), and the extracted reference material under `docs/native-supporting/`.
* `assets/ds/shapes/*.svg` (20 files, compiled in at `src/shape_library.rs:69`).

**Finding**

* **Icons.** `docs/evidence-ui.md:5` says the icons were "extracted from the inline SVG registry" of Design Space's bundle, and `:209` says they are "copied verbatim from the registry". 22 of them ship in the binary.
* **Thumbnails.** `:310` says the original shape thumbnails were copied from Cricut's local content cache into `assets/ds/shapes/previews/`.
* **Shape SVGs.** These are documented clean-room reconstructions of simple primitives, measured from those thumbnails. The risk is low, but no provenance note sits beside them.
* **Fonts.** These are fine: Inter and Space Grotesk are OFL with licence texts. `assets/fonts/LICENCE-NOTE.txt:1` still names the product "Shape Studio".
* **Name.** README:3 calls the project "open-source". The name "Open Design Space" echoes Cricut's product name.

**Why it matters**

The project cannot be published or redistributed under an open licence while it ships proprietary icon artwork verbatim and commits Cricut's thumbnails and screenshots. The name is also a trademark risk for a public project.

**Recommendation**

1. Delete `assets/ds/shapes/previews/`, which nothing references.
2. Replace the 22 used icons with an openly licensed set (Lucide or Phosphor) or with original drawings. `icons.rs` already draws some glyphs itself. Then delete the other 94.
3. Decide whether the screenshots and the extracted reference material under `docs/` belong in a public repository.
4. Add a provenance note for the shape SVGs.
5. Fix the "Shape Studio" note.
6. Consider a rename before any public release.

**Validation**

* `rg -l 'copied verbatim' docs` maps only to assets that have been removed.
* `assets/ds/shapes/previews` does not exist.
* Every file under `assets/` has a stated licence.

### AUDIT-005: No single edit-command model

**Severity:** High
**Category:** Architecture
**Confidence:** Confirmed
**Scope:** Systemic
**Sources:** B-01 (root), with symptoms B-02 (enable rules disagree) and B-05 (five unit-counting loops). Concrete bug linked: AUDIT-006.

**Locations**
* **Dispatch.**
  * `src/ui/chrome.rs:31` `MenuCommand`, applied at `src/ui/mod.rs:297`
  * `src/ui/canvas.rs:121` `View.command`, drained at `ui/mod.rs:505`
  * `src/ui/context_menu.rs:25` `Action`
  * `src/ui/selection.rs:180` `Action` and `:187` `Pick`
  * `src/ui/toolbar/combine.rs:9` `Pick`
  * `src/ui/toolbar/flip.rs:6` `Flip`
  * `src/ui/toolbar/effects.rs:32` `Effect`
  * `src/ui/toolbar/text.rs:28` `TextChange`
  * `src/ui/layers_actions.rs:20` `Action`
  * `src/ui/layers_panel.rs:16` `RowAction`
  * `src/ui/canvas.rs:675` `keyboard`
  * `src/ui/container_panel.rs:74-78`
* **Enable rules.**
  * `src/ui/mod.rs:233` `can_link: self.selection.len() >= 2`
  * `src/ui/context_menu.rs:110-121` `Action::enabled`, overridden for Align at `:279-282`
  * `src/ui/selection.rs:220-231` `units_in`
  * `src/ui/layers_actions.rs:41` `design.units(selection).len() >= 2`
  * The model's real rule is at `src/links.rs:47-52`
* **Unit loops.**
  * `src/design.rs:891` `units`
  * `src/design.rs:1009-1023` `align_units`
  * `src/containers.rs:101` `units_of`
  * `src/composition.rs:75` `units`
  * `src/ui/selection.rs:220` `units_in`
  * Bounds are an anonymous 4-tuple (`containers.rs:25`), while `snap::Aabb` already names the same thing.

**Finding**

The same design edits reach `Design` through about a dozen paths, each with its own enum, enable rule and apply arm:
* Delete has three implementations, and the selection afterwards differs between them.
* Arrange has three, with different wording.
* Flip has two, with different behaviour (AUDIT-006).

`MenuCommand` mixes two kinds of command. App commands (Save, Undo, Make) need `CricutLite`. Pure design edits are deferred through `View.command` for one-undo-step reasons that `History::observe` already guarantees.

Group and Attach have four enable rules, none of which matches the model:
* `selection.len() >= 2`
* `units_in >= 2`
* `Design::units(..).len() >= 2`
* none at all on the keyboard

`Design::link` refuses any selection that includes a container. So with a container and a shape selected, Group and Attach are enabled on four surfaces and do nothing when clicked.

The context menu's Align enable arm never runs in production, because `show` overrides it. The unit test `combine_and_align_follow_their_toolbar_rules` asserts that dead arm, so it would stay green if the visible rule broke.

**Why it matters**

Every new operation multiplies work across surfaces: a variant, a label, an enable rule and an apply arm in each. The divergence is already visible to users (AUDIT-006, and the dead Group and Attach buttons) and in the copy (AUDIT-023). Spec 21 will add operations to every surface.

**Recommendation**

Add `src/edit.rs` with one `Edit` enum beside the model, giving it `check(&Design, &[u64]) -> Result<(), Blocked>` and `apply(&mut Design, &mut Vec<u64>)`. This is the shape `path_edit::NodeAction` with `NodePath::check` already has.

* Move each precondition into the model. For example, add `Design::can_link`, and have `link` call it.
* Shrink `MenuCommand` to app commands plus `Edit(Edit)`.
* Delete these: `selection::{Action, Pick}`, `flip::Flip`, `context_menu::Action`, the dispatch half of `layers_actions::Action`, the edit variants of `RowAction`, and `View.command`.
* Replace the five unit loops with one `Design::units_by(ids, UnitKey)` that returns `Unit { ids, bounds: Aabb }`.
* Migrate callers and delete the old enums in the same change, with no adapters.

**Validation**

* `grep -rn "enum .*Pick\|enum RowAction\|enum Flip" src/ui` returns no edit enums.
* A table test asserts that each `Edit` is enabled identically on every surface that shows it, including container plus shape.
* `grep -n "a.0.min(b.0)" src` returns nothing.

### AUDIT-006: Toolbar Flip flips only the first selected shape

**Severity:** Medium
**Category:** Correctness
**Confidence:** Confirmed (code). Not exercised in the GUI.
**Scope:** Local
**Sources:** B-03. Symptom of AUDIT-005.

**Locations**
* `src/ui/toolbar/mod.rs:217-224`
* `src/ui/selection.rs:307-310` and `src/transform.rs:138` (`flip_many`)

**Finding**

The toolbar toggles `flip_x` or `flip_y` on `selection.first()` only. The action bar and the context menu mirror every selected shape across the selection frame through `transform::flip_many`. With two shapes selected, the same label gives different results depending on the surface. README says the toolbar's Flip edits "the selection". The only toolbar Flip test uses a single shape.

**Validation**

A kittest selects two shapes apart, uses toolbar Flip Horizontal, and asserts that their x positions swap.

### AUDIT-007: `replace` and Split Letters ignore containers

**Severity:** Medium
**Category:** Correctness (domain invariant)
**Confidence:** Confirmed for the code paths. The Split outcome is traced, not run.
**Scope:** Systemic
**Sources:** A-02. The same gap appears as A2 and A8 in `docs/specs/21-review.md`.

**Locations**
* `src/design.rs:923-934` `replace`: removes only `ids`. Callers are Combine, Slice, Sticker, Flatten and Unflatten (`design.rs:886, 919, 967`; `flatten.rs:19, 29`)
* `src/design.rs:719-723` `remove_many` and `:825-826` `duplicate` expand through `with_descendants`
* `src/containers.rs:652-658` `repair` clears parents that no longer name a container. A-02 cited `643-648`; the line reference is corrected here
* `src/text_ops.rs:104-115` `ungroup_text` and `:61-83` `place` (`..source.clone()`)
* `src/flatten.rs:94-112` `placed_part`
* `src/links.rs:47-52` `link` refuses containers

**Finding**

Three policies exist for a container that an operation consumes:
1. Delete and Duplicate take the whole subtree.
2. `replace` removes the container only. `settle` then promotes its children to the top level, so containment and layout vanish without warning.
3. `ungroup_text` does not use `replace`. Spec 21's review says it does; the code shows it does not. It builds each letter with `..source.clone()`, so splitting a container text gives every letter `container: Some(role)` and the source's `parent`. The follow-up `group` then fails, because `link` refuses containers. The user asked for grouped letters and gets N ungrouped containers.

`unflatten` restores a container part with its role but without its children.

**Why it matters**

The same object loses its children through Weld, Flatten or Split, but deletes them through Delete. Split creates a state that no UI path can otherwise reach. Spec 21's Compounds build on `replace`, where the same gap means cutting children twice.

**Recommendation**

Add one `Design::consume(ids) -> (at, parent, subtree)` primitive that every destructive operation calls:
* It expands through `with_descendants`.
* It applies one stated subtree policy.
* It returns the slot and the parent.

Shapes built from a source (`place`, `placed_part`) start from `container: None, parent: None, link: None`.

**Validation**

* For each of Weld, Slice, Flatten, Sticker, Split Letters and Unflatten, a unit test uses a container that has children.

### AUDIT-008: Flaky kittests from preview repaints and a process-global font catalogue

**Severity:** Medium
**Category:** Testing / Concurrency
**Confidence:** Confirmed (reproduced)
**Scope:** Systemic
**Sources:** A-03 (root cause), C-06's and C-08's mention of the flake, and A-08 (folded in). D's alternative hypothesis, that the scan thread's start-up repaint is the cause, is superseded by A's reproduction and has been dropped.

**Locations**
* `src/ui/font_preview.rs:66-75` loader thread. `:72` is `ctx.request_repaint()`, called once per face
* `src/system_fonts.rs:23-24` `static CATALOGUE: OnceLock<Catalogue>`, `static SCAN: Once`
* `src/system_fonts.rs:43-54` `start_scan`: only the first caller's context is ever notified
* `src/ui/mod.rs:111` every app instance calls `start_scan`
* `src/ui/tests_spec15.rs:40-41`, `src/ui/tests_spec10.rs:55-56` (open the font menu, then call `harness.run()`)

**Finding**

When the font menu opens after the scan has finished, every row asks `font_preview::family`. Each call queues a load on a loader thread, which repaints once per face. The faces trickle in over several frames. If more than four consecutive steps end with a repaint request, `Harness::run` panics, and whether that happens depends on parallel-test contention. The failure output names `font_preview.rs:72`. `cargo test ui::` failed 2 of 13 runs; the spec 15 test alone passed 6 of 6.

The spec 10 test is also order-dependent. It takes the loader path only if some other test has already filled the global `CATALOGUE`.

**A-08 folded in.** The same global has a production symptom. Before the scan lands, `system_fonts::face` returns `None`, so system-font text lays out and outlines in Inter. Home > Make in that window cuts Inter glyphs. A family that is not installed also cuts in Inter, with a warning shown only in the font menu. Spec 21's review (A3) shows the same gap becomes permanent once layout is cached.

One change fixes both. Pass a font catalogue handle into the app, with an explicit readiness state and a generation counter:
* Tests inject a ready, deterministic catalogue.
* Make, and spec 21's cache key, read readiness and the generation from the same handle.
* The Make gate itself is a small extra step on top.

**Why it matters**

* A flaky suite trains people to re-run failures, which hides real regressions.
* It makes CI (AUDIT-012) unusable.
* Users can get a cut that does not match the canvas.

**Recommendation**

* Replace the `CATALOGUE` and `SCAN` globals with a `FontCatalogue` handle owned by `CricutLite` and passed to the font menu, text layout and Make. It exposes `ready()` and `generation()`.
* Make preview loading injectable, so tests can run it synchronously or drain it.
* In production, request one repaint per drained batch rather than one per face.
* Gate Make (or `compose`) on readiness when the design has system-font text, and show the missing-family warning on Prepare.

**Validation**

* `for i in $(seq 20); do cargo test -q; done` passes every time.
* A test lays out system-font text, flips the catalogue to ready, and asserts the geometry changed.

### AUDIT-009: Project file paths come from the untrusted `id` in the JSON

**Severity:** Medium
**Category:** Robustness / Security
**Confidence:** Confirmed (code)
**Scope:** Local
**Sources:** D-02

**Locations**

## 7. Systemic Themes

* **Parallel specs re-implemented shared concepts per surface.** The dispatch paths, enable rules, unit loops, labels and the toolbar Flip all diverged because no spec owned "an edit". The same pattern shows in the test harness copies.
  * Findings: AUDIT-005, 006, 013, 022, 023.
  * The model layer avoided it where one module owned the concept: `containers::settle`, and `path_edit`'s `check`/`apply`.
* **The file boundary is trusted.** Imported SVGs, project JSON and project ids flow into the model with no validation. Load errors are swallowed, and save errors are invisible.
  * Findings: AUDIT-002, 003, 009, 017, 019.
  * `settle`'s load-time repair is the right place to add a `sanitise` step.
* **There is no user-facing error channel.** Failures go to `eprintln!`, a `None`, or `filter_map(.ok())`. Unsaved state is not tracked.
  * Findings: AUDIT-001, 002, 027.
* **Destructive operations lack one subtree policy.** Delete, Duplicate, Weld, Flatten and Split each treat containers differently. Spec 21 multiplies the cases.
  * Findings: AUDIT-007, and 21-review A2 and A8.
* **Tests look complete but leave the risk unchecked.** There are 439 passing tests, yet snapshots are not compared, the machine-facing output and the unhappy paths are untested, one test asserts an unused rule, and the suite is flaky with no CI to notice.
  * Findings: AUDIT-005 (dead Align arm), 008, 011, 012, 014.
* **Process-global state leaks across boundaries.** The global font catalogue makes the tests order-dependent and the cuts timing-dependent. The Align To preference sits outside app state.
  * Findings: AUDIT-008, 026.

### Dependencies that appear unused
* None. Production code never references `image` directly, but it supplies PNG decoding for `egui_extras::install_image_loaders`, which Home thumbnails use. Add a comment in `Cargo.toml` so that nobody removes it.

### Abstractions that appear redundant
* `View.command` and the `Option<MenuCommand>` deferral, since `History::observe` already gives one undo step per frame.
* The wrapper enums `selection::Action` and `context_menu::Action`, and `toolbar::flip::Flip`, which duplicates `transform::Axis`.
* `TopBar`'s eight capability booleans (`chrome.rs:68-85`).
* The curve fitting in `path_edit.rs:815-960` is generic geometry and belongs in `geometry`.

## 9. Strengths Worth Preserving

* **Undo.** Whole-frame snapshot undo with gesture folding: any edit in a frame is one undo step, with no per-command undo code. This is what makes a single command model cheap.
* **Containers.** `containers.rs` states its invariants in the module doc and restores them in one idempotent `settle`, which returns early and runs once per frame and on every load. It has 30 tests, including idempotence and repair of dangling and cyclic parents.
* **Command template.** `path_edit::NodeAction` with `NodePath::check -> Result<_, Blocked>`, whose reasons feed disabled tooltips. AUDIT-005 should copy it.
* **Pure rules.** `layers_dnd.rs` keeps the drop rules pure, separate from the UI drag gesture code.
* **Model-owned queries.** The container queries `can_contain`, `contain_wraps` and `has_container` are used consistently.
* **Make flow.**
  * The pure `device::reduce` and the `MakeFlow` state machine with an outbox, plus a `Transport` trait and channel-only threading, mean no shared state.
  * The `proto_enum!` macro declares each wire enum once.
* **Serde compatibility.** Every spec added `#[serde(default)]` fields with an "old project still loads" test.
* **Ids.** Shapes and links share one id counter. Project ids add a per-process sequence to the timestamp.
* **Input guards.** `parse_value` rejects non-finite input. Font faces are validated with `ttf-parser`, and previews are capped at 4 MiB before egui sees them.
* **Background work.** Font scanning and preview loading run off the UI thread.
* **Test isolation.** `Fixture` gives every UI test its own temp projects directory.
* **Tests that encode rules.** `flow_screens_paint_only_tokens_and_flow_kit_widgets` enforces a design rule in a test rather than in prose.
* **Hygiene.** `Cargo.lock` is committed, `clippy --all-targets` is clean, and the `dead_code` allows give reasons. The commercial Design Space fonts were kept out of the tree, and the OFL fonts ship with their licences.
