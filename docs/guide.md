# Kerf guide

How Kerf works, screen by screen, and where each part lives in the code. The [README](../README.md) is the short version.

Kerf is a small egui desktop cutting-machine editor, with its own canvas and a full Make flow, for personal use. It is not published. It is a bare-bones cutting UI, with no paid, account or marketing surfaces. A simulated machine drives the flow. Every message to and from the machine uses Kerf's own bridge format, so the Payload panel shows what a real bridge would receive.

The behaviour it models is documented in `docs/evidence-webapp.md` and `docs/evidence-electron.md`.

## Run

```sh
cargo run --release
cargo test
```

## Architecture

The crate has one UI thread and one simulator thread. They share no state; two `std::sync::mpsc` channels carry `BridgeMessage` values between them. The UI drains the inbound channel with `try_recv` once per frame and asks for a repaint every 50 ms while a Make flow is open. Nothing on the UI thread blocks.

### Commands

Every design edit a surface can make is one `Edit` value in `src/edit.rs`. `Design::check(&edit, ids)` holds its enable rule and returns `Blocked` when it cannot run, whose `reason()` is the disabled control's tooltip; `Design::apply` runs it only when the check passes and returns the ids the user holds afterwards. Every surface (the File and Edit menus, the keyboard, the edit toolbar's popovers, the selection action bar, the context menu, the Layers action bar and rows, and the inspector) builds its entries from the one table in `src/ui/commands.rs`. Design edits run through `edit::run`. Clipboard actions use that command table too, while `ui/clipboard.rs` handles platform I/O; Cut writes the package before `Edit::Delete`, and Paste and Paste Style use design edits. Layers row buttons run on the row's objects and leave the selection alone. App commands (New, Home, Save, Export, Prepare for Design Space, Undo, Redo, Make, Preview, opening a project, the tab commands, the command palette and the View settings) are `AppCommand`, with their own check against the design and history. Each frame is one undo step, so an edit applies in the frame it is picked. Node editing keeps its own `NodeAction` and check in `path_edit.rs`.

`proto_enum!` declares each wire enum once, with its numeric code and protobuf name. Enums serialise by name, as protobufjs `toObject({enums: String})` does.

### Wire format

Field names and types follow Kerf's own protobuf message definitions, one per interaction: the common bridge envelope, material selection, the selected tools and tool info, the mode, the mat path data, the transform matrix, progress, the serialised device and the interaction handle. The JSON is camelCase.

Two choices are worth noting:

- Kerf sends plaintext `pathData` with `pathEncrypted: false`; it does not encrypt requests.
- Kerf uses a fixed table of plausible material settings rather than fetching them from a server.

`pathData` is the square in its own frame, for example `M0 0 L144 0 L144 144 L0 144 Z` for a 2 in square. The `Matrix` transform places it at its packed position on the current mat (see Mats below), and Mirror flips across the mat width. Each project copy is packed like any other unit, so no path is ever sent outside the cutting area.

Pressure adjusts by a per-material delta. More gives `pressure + deltaAdjustment[2]`, Less gives `pressure + deltaAdjustment[0]`, and Default leaves it unchanged. `originalPressure` keeps the base value.

### Simulated machine

The simulator thread walks the happy path inferred in the evidence:

```
riMATCUT                       -> riSingleDeviceConnected (Kerf Studio Pro over USB and Bluetooth)
riSelectDevice                 -> riDeviceOpenSuccess, riWaitingOnMaterialSelected
riMaterialSelected             -> riMATCUTGettingDevicePressureSettings, riSendToolArray
riToolInfoReceived             -> riMATCUTNeedPathData
riMATCUTSetPathData            -> riWaitOnMatLoad
719 (Load)                     -> riMatLoaded, riWaitOnGo
720 (Go, the Go button)        -> riGoPressed, then riMATCUTSetProgress every 100 ms, 0 to 100 %
                               -> riMATCUTCompleteSuccess, riWaitOnMatUnload
719 (Unload)                   -> riMatUnloaded, riComplete
```

During the cut, 721 toggles pause (`riDevicePaused` and `riDeviceResumed`). 717 aborts the cut: before Go the machine answers `riMATCUTAbortCut` and `riComplete`, and from Go onwards it answers `riMATCUTAbortCut` and `riWaitOnMatUnload` so the loaded mat can come out. 720 while waiting to unload cuts again ("Cut more"). Path data after `riComplete` starts a rerun. The number of passes comes from `multiPass` in the tool info the UI sent.

Rerun after a complete cut sends only the path data, because the machine still holds the material and tools. Rerun after a Cancel starts the mat again from Set, because the cancel may have come before `riMaterialSelected` or the tool info was sent.

`Transport::send` and `Transport::try_recv` return `Disconnected` when the machine's end has gone. The flow then shows Machine disconnected with Back to canvas instead of waiting forever. A remembered machine that is missing from the device list reopens the machine modal with a notice naming it.

`device::reduce` maps each inbound status to a `deviceState`. For example, `riWaitOnMatLoad` maps to `WaitingOnLoad` and `riWaitOnGo` maps to `ReadyToGo`. Statuses with no mapping leave the state unchanged.

### Mats

`composition::compose` decides the mats, following the rule inferred in `docs/evidence-ui.md` section 6. Visible shapes that are not Guide go on mats. An Attach link is placed as one unit and keeps its members' relative positions; every other shape, group members included, is a unit of its own. A unit with any Print Then Cut piece goes onto a print page. Every other unit's mat is keyed by colour: a cut unit (Basic Cut, Wavy Cut, Perforate) by its fill, and Pen, Score, Foil, Deboss and Engrave shapes by the cut shape they are attached to, or by their own fill when unattached. Print pages come first, then cut mats in first-use colour order. Units pack left to right and top to bottom inside the cutting area less the 18 pt padding, a quarter inch apart, spilling onto a further mat of the same colour when one fills. A unit too large for the mat gets a mat of its own, flagged "Too large for this mat" in the preview. Each mat's label dedupes its operations and sorts them Print Then Cut first, then in plot order (Score, Pen, Deboss, Engrave, Foil, Perforate, Wavy Cut, Basic Cut), for example "Score, Pen, Basic Cut".

Kerf composes Print Then Cut pages as recorded in `docs/evidence-webapp.md` ("Print Then Cut composition"). Colour plays no part, so a red sticker and a blue one share one white page. The page is Letter or A4 paper, picked in Prepare's Paper Size dropdown and defaulting to Letter for inches and A4 for centimetres. Images pack by their bounding boxes inside the printable area, which is the paper less 58.25 pt top and left and 67.75 pt bottom and right, so Letter gives 6.75 x 9.25 in. They go left to right in canvas order with 10 pt between them, each copy after the last, and an image that does not fit starts a new page. An image larger than the printable area gets a page of its own, and Prepare blocks Continue with "Image is too large for Letter paper". Each page opens on a Print step before Set. It shows the page with the printable area dashed, an Add Bleed toggle (on by default) and Save print sheet (PDF), which writes `{project} - Print 1.pdf`. The print sheet holds only the artwork: each image filled in its colour at its place on the page, and a sticker or other flattened image as its parts in their own colours, white backing included. An uploaded image prints its pixels inside its cut line, turned and mirrored as it is placed, at its own resolution up to 300 dpi at its placed size; a flattened image part prints its pixels the same way. The PDF embeds each picture as a Flate-compressed RGB image with its transparency as a soft mask. With Add Bleed on, the art is first drawn grown by 0.03 in and then drawn again on top, the way Kerf stamps its bleed; for an image the grown outline is filled with the picture's edge pixels repeated outward. An image whose file is gone prints its cut line in its colour. A pattern fill (see Precision) prints the same way: a tiled pattern is rendered across its outline at 300 dpi and clipped to it, and its bleed continues the tiling. It carries no registration marks, sensor box or text, so a cutting machine cannot register the cut from this sheet alone; the Print step says so. Next goes on to Set, and a cut mat never shows the Print step.

Make cuts one mat at a time. The Set Load Go screen reads "Mat 1 of 3", and the Load step lists only the current mat's tools. Once a mat is unloaded, Next Mat starts a fresh `riMATCUT` interaction for the following mat and returns to Set; the last mat offers Back to canvas instead. Changing the Material Size or the project copies recomposes the mats. Copies pack unit by unit after the first copy and spill onto further mats, so 20 copies of a 3 in square fill a 12 x 12 mat three by three and need three mats.

Once a machine connects, the app remembers it. On the next Make, Continue goes straight to Set and the app reselects the machine without opening the modal.

The Payload panel on the right shows the last message sent and the last message received as pretty JSON, with the `ri*` name and number in the header.

### Optimise layout

Packing places each unit by its bounding box, so a ring, an L or a set of letters wastes most of its box, and a long strip that would fit sideways spills onto another mat. **Optimise layout**, above the Mats list in Prepare, packs every cut mat's pieces as tightly as their real outlines allow. A piece is a placement unit as composition defines it (an Attach link, a cut container with its children, or a lone shape), and it moves and turns rigidly, so Pen, Score and Foil lines stay on the shape they belong to. Pieces never change colour, so each colour keeps its own mats, though it may need fewer of them. Print Then Cut pages keep their own packing.

The **...** button beside it opens the settings:

- **Rotation.** None, 90 degrees (the default), or Free in steps of 5, 10, 15 or 45 degrees.
- **Spacing.** The minimum gap between pieces, 0.125 in by default, in the app's units. The mat keeps its 18 pt padding.
- **Use holes.** On by default. Small pieces may go in the holes of larger ones, such as letters inside a frame.

**Grain lock.** Wood veneer, faux leather and directional glitter have a direction. Click **Grain** beside the Colour caption in the inspector to lock the selection's grain. A piece with any locked member only turns 0 or 180 degrees. The command palette's Lock grain and Unlock grain do the same.

The packing runs on its own thread for about 1.5 seconds, so Prepare stays responsive and shows a progress bar and **Cancel optimise**. Cancel leaves the mats as they were. When it finishes, Prepare shows the nested mats and a card such as "Material: 7.5 in to 3.25 in, 57 % less", where each length is the lowest placed point on each cut mat, added up, before and after. "Mats: 3 to 2" follows when the count changes. **Undo optimise**, or Cmd+Z while the card shows, restores the previous layout in one step, and Redo on the canvas brings it back.

The layout saves with the project, together with a fingerprint of every cut piece's outline, operation and colour, the mat size and the copies. Make uses the layout only while the fingerprint matches. After any such change, Prepare falls back to packing and shows "The design changed since the layout was optimised" with **Optimise again**.

**How it packs.** Each piece, in each allowed rotation, is rasterised once with tiny-skia onto cells of half the spacing (0.02 to 0.05 in), filled and then stroked by the spacing plus a cell, so pieces whose cells do not touch are at least the spacing apart on their exact outlines. The mat is a grid of `u64` rows, so testing a position is a few word ANDs. Pieces go largest first, each at the first free cell scanning rows then columns, in the rotation that leaves the shortest used length. A seeded loop then swaps neighbours in that order and keeps the best result by mats used, the last mat's length and the total length, for a fixed number of rounds, so a design always nests the same way. Placements come back as exact inches and angles, and the payload turns each piece about its centre before Mirror, so cut paths are never rasterised.

## Open cutters

Kerf can cut on machines that use open protocols: an HPGL vinyl cutter, or a GRBL board driving a diode laser or a pen plotter. Each is an **open device**, described by a saved profile and reached over a USB serial port. The same Prepare, Set, Load, Go, Cutting and Done screens drive it. Nothing here touches Cricut's protocol, its encryption or its key material.

**Profiles.** The machine modal lists the simulated machine first, then each saved profile under Open Devices, then **Add device**. Add device starts from a preset: "HPGL vinyl cutter" (9600 baud, 40 units per mm, 0.25 mm drag knife, 1 mm overcut), "GRBL laser" (115200 baud, laser power up to S1000) or "GRBL pen plotter" (115200 baud, pen down `M3 S30`, pen up `M5`). The setup screen edits every field: protocol, baud, units per mm, origin corner, axis swap, work area, tool, speed range, force range, overcut, XON/XOFF and the HPGL identify and abort strings. Lengths show in the app's units. Profiles live in `settings.json` with the last device used, so the next Make starts on it. Prepare shows the machine with **Change machine**.

**Plug-in detection.** When the machine modal opens, Kerf reads the USB descriptor of each serial port and promotes a recognised machine to a **Detected on USB** section above Open Devices. A known open cutter, matched by its USB-serial bridge (FTDI, CH340 or CP210x), shows **Set up**, which opens the setup screen on the matching preset with the detected port filled in. A Cricut machine is named from its USB product string, for example "Cricut Maker 3", and shown an honest notice in place of a connect button. Kerf cannot send cuts to a Cricut machine, because its cut protocol is encrypted and authenticated by Cricut's servers, so the notice points to Cricut Design Space for cutting and to Kerf for design and SVG, DXF or PDF export. Detection reads the descriptor only and never opens the Cricut port. An unrecognised port is not promoted, but stays available in the setup screen's port picker. The known machines live in one table in `output::machines`.

**The port and the connection test.** The setup screen's port dropdown lists `serialport::available_ports()`, with the USB product and maker where the OS reports them, and **Refresh** scans again. **Test connection** opens the port on the device thread and sends only an identity query. GRBL gets a bare newline and has 2 s to send its `Grbl` banner; if it does not, it gets `$I`. HPGL gets the profile's identify query (`OI;` by default). A cutter that never answers passes with "Port opened; this cutter does not report an identity". Continue is enabled only after a passed test.

**Composition and mapping.** An open device composes at its work area, so Prepare packs the design onto that sheet. Load Type is hidden; Copies and Mirror stay. The Project Preview card shows the work area's size where the simulated machine shows its mat style. Print Then Cut mats are skipped, with the notice "Print Then Cut needs a registration step this device does not have". Set lists the same materials and shows the derived values: Cardstock on the HPGL preset reads "Speed 295 mm/s, Force 96". Speed is linear in the material's cut speed over the profile's speed range. Force, and laser power, are linear in the adjusted pressure over 0 to 1500, clamped to the profile's range, so More and Less move them by the material's delta. A material's passes repeat the cut strokes, never the draw strokes.

**Ordering.** Strokes run in plot order, so drawing finishes before cutting. Within that, inside-out: a stroke is cut only after every stroke inside it, so letter counters go before letters and letters before the card under them. Among the strokes that are ready, the head takes the nearest entry point, starting from the origin. A closed ring starts at its vertex nearest the head, and an open stroke may run backwards.

**Blade offset and overcut.** For a drag knife, each point shifts forward along the travel direction by the blade offset. At a corner sharper than the swivel threshold, the path goes round an arc of the offset's radius about the true corner, so the trailing tip turns on the line instead of rounding it. Closed cuts start with a short lead-in, so the blade lines up before it enters. A closed cut runs on past its start by the overcut length. Draw strokes never overcut.

**Output.** HPGL is `IN;`, `VS` and `FS`, then `PU` and `PD` per stroke in whole plotter units, ending with `PU;` and a park at the origin. It streams in chunks of at most 256 bytes, paced by the estimated drain time unless the profile turns on XON/XOFF. G-code is `G21`, `G90`, then `G0` travel and `G1 ... F` moves in millimetres to three decimals, with the pen commands and a `G4` settle around each stroke, or `M4`/`M3 S` and `M5` for a laser. A laser draws Pen, Score and Engrave at 30 % power. GRBL streams one line at a time and waits for `ok`. `error:N` or `ALARM:N` stops the job, and the flow shows the code and its meaning.

**Dry run.** On the Go step, **Save to file** writes the mat's job to `<project> - Mat 1.hpgl` or `.gcode` from a save dialog. It goes through the same streaming code as the port, into a file instead, so the file holds exactly the bytes the port would receive.

**Safety.**

- Nothing moves before Go. Connecting and testing send only the identity query, and the flow starts a job only from Go.
- Pause sends GRBL's feed hold `!`, and Resume sends `~`. HPGL has no standard pause, so Pause stops streaming, and the Cutting screen says the cutter finishes the moves it has already received.
- Cancel stops streaming at once. For GRBL it then sends `!`, the soft reset `0x18` and `M5`. For HPGL it sends `PU;` plus the profile's abort string.
- Closing the Make flow or quitting the app while a job runs cancels it first.
- A laser profile shows "Laser: wear eye protection rated for this wavelength and never leave the machine running unattended." on the Go step.
- Kerf never sends `$H` (homing) or `$X` (alarm unlock).

### Using an open cutter

**Connect an HPGL vinyl cutter.**

1. Plug in the cutter's USB serial cable and turn the cutter on.
2. Click **Make**, then **Continue**, then **Add device**, and keep the "HPGL vinyl cutter" preset.
3. Set the baud to the rate in the cutter's manual; most cutters use 9600. Set the origin to the corner where the cutter's head parks, and turn on **Swap X and Y** if the cutter feeds the material along its own X. Set the work area to the cutting width and the length of material you load.
4. Set the blade offset from the blade's data sheet. 0.25 mm suits a standard 45° blade.
5. Choose the port. On macOS a USB serial adapter shows as `/dev/cu.usbserial-...` or `/dev/cu.usbmodem...`.
6. Click **Test connection**, then **Continue**.

**Connect a GRBL laser or pen plotter.**

1. Plug in the GRBL board.
2. Click **Make**, then **Continue**, then **Add device**, and choose the "GRBL laser" or "GRBL pen plotter" preset.
3. Leave the baud at 115200 unless the board says otherwise. Set the origin to the corner where the machine homes, and set the work area to its travel.
4. For a laser, set **Full power S** to the board's `$30` value. For a pen plotter, set **Pen down** and **Pen up** to the commands that move your servo or Z axis.
5. Choose the port, click **Test connection** and wait for the `Grbl` banner, then click **Continue**.

**Run a first safe test.**

1. Draw one small square, about 1 in (2.5 cm), and click **Make**.
2. On Set, choose a light material. On Go, click **Save to file** and read the file: check that the coordinates are inside your work area and that the first move goes where you expect.
3. Place scrap material at the origin corner. For a pen plotter, use a pen. For a laser, use low power: set **Full power S** well below the maximum, wear eye protection rated for the laser's wavelength, and stay at the machine.
4. Click **Go**, and keep a hand near the machine's power switch. Use **Cancel** to stop.

## Cut preview

The cut preview shows how the machine will move over a mat before anything is sent. Open it with **Preview cut** under the mat in Prepare, which opens on the selected mat, or with **View > Cut preview** on the canvas, which composes the design for the last device used and its preferred mat, as Make would. Escape or the close button dismisses it.

It plays the exact strokes Make sends: `output::mat_toolpath` is the one pipeline behind both the preview and an open device's job, so the order, the drag-knife compensation, the overcut and the repeated passes are the ones the machine gets. Draws run before cuts, inside-out, nearest first, from the origin and back to it. Completed work moves are solid in their operation's made style, remaining work is a faint line, and travel between strokes is dashed. A violet dot marks the head. **Play** and **Pause**, a scrubber over the whole run, **Restart**, speeds of 1x, 4x, 16x and 64x, and **Previous mat** and **Next mat** when there are several mats, drive it. With a drag knife, **Show original path** overlays the uncompensated outline faintly.

**The estimate.** `output::estimate` times each move: work length over the work speed, travel length over the travel speed, and a tool change each time the tool lowers onto a stroke. Each pass of a cut stroke counts again; draw strokes count once. An open device uses its profile and the material: the mapped work speed, the top of its speed range for travel, and a pen's settle time. The simulated machine has no published speeds, so it uses a fixed nominal table by the material's cut speed, and the preview labels its times as a nominal estimate. Before Set has chosen a material, times assume the first material, Cardstock, and the preview says so. The readout shows elapsed and total time ("0:42 of 3:15") with the work and travel lengths, and Prepare's mat list shows each mat's total time beside its label.

**Material used.** "Material used 4.75 x 3 in (11 % of mat)" is the bounding box of the mat's pieces at their packed positions, against the cutting area: the mat less the 18 pt padding on each side.

## Tests

`cargo test` runs everything and must pass every time: the suite is deterministic, with no sleeps or wall-clock waits. CI (`.github/workflows/ci.yml`, one `macos-latest` job) runs `cargo fmt --all --check`, `cargo clippy --all-targets --locked -- -D warnings`, `cargo test --locked` and `cargo deny check advisories`. `rust-toolchain.toml` pins the toolchain those use.

### How the tests are organised

- **Unit tests** sit beside the code they test, in each module's `tests` module: geometry, composition, the payload builders, the Make state machine, projects, sanitising and so on.
- **UI tests** drive the real app headlessly with `egui_kittest`. Each spec's behaviour lives in `src/ui/tests_specNN.rs`, and the older cross-cutting ones sit in `src/ui/tests_core.rs`. `ui/mod.rs` is production code only; its test modules are declared in one `#[cfg(test)]` block of `mod` lines.
- **Fixtures.** `tests/golden/` holds golden payloads. `tests/fixtures/malformed/` holds the hostile inputs the audit found (a 1e12 px SVG, an overflowing `width_in`, an id that climbs out of the projects directory); they must load or be refused without a panic, a hang or an unbounded allocation.
- **Timing.** `#[ignore]`d tests measure frame times: the idle frame with 200 shapes, and the heavy benchmark design (see Benchmark). Run them with `cargo test --release -- --ignored --nocapture`.

### The harness

`src/ui/test_harness.rs` is the one place a UI test builds the app. `snapshot_harness(size)` starts it over its own temp projects directory, so no test touches the real app data, and opens a blank tab from Home so the test starts on the canvas; `launch(root, size)` reopens the same directory, as relaunching does, and stays on Home like the app. Every harness gets `FontCatalogue::fixture()`, two in-memory families named "Fixture Grotesk" and "Fixture Display", so font tests do not depend on the machine's fonts or on scan timing. Input helpers (`click_at`, `drag_along`, `move_to`, `key`, `right_click_at`) and pixel helpers (`pixel`, `bare`, `rect_of`, `any_near`) live there too; add new ones there rather than in a spec file.

The Make flow talks to `SimulatedMachine` on its own thread. `pump(harness, what, done)` steps the app until `done` holds, blocking on the machine's next reply between frames rather than sleeping, so it waits exactly as long as the conversation takes. A 10 s guard only turns a silent machine into a failure. The same rule holds for the other threads: a test waits on a worker's own reply and never sleeps. The image worker has `wait_answered`, the nesting worker `wait_finished` (it joins the thread) and the texture loader `wait_loaded`, each compiled for tests only, and `tests_spec28::wait_for` steps frames between the image worker's answers. `ticking_harness` slows the machine's cut to catch a frame mid-cut, and `machine_harness` takes a machine the test made, for example one it can kill.

### Snapshots

The tests render through wgpu, so they need a GPU (Metal on macOS). A test says what it drew in one of three ways:

- `assert_snapshot(harness, "name")` (and `assert_flow_snapshot` inside the Make flow, `assert_image_snapshot` for a bare image) compares the frame with the committed baseline `tests/snapshots/name.png` and fails if any pixel differs by more than the 0.1 threshold. 79 baselines cover the editor, operations side by side, the selection chrome, drawn and warped shapes, text layout, the artboard, Project Preview, the icon sheet, Home and each Make screen.
- `frame(harness)` and `flow_frame(harness)` return the settled frame, and the test asserts pixels in it with `pixel`, `rgb` or `bare`. Nothing is written.
- `look_at_snapshot(harness, "name.png")` writes `target/snapshots/name.png` for a person to open and compares nothing, so a test that calls it asserts what it drew some other way. Only the two reference-sized frames use it.

`save_snapshot`, the older name of `look_at_snapshot`, still forwards to it for specs 11, 13 and 20 until those Layers tests are converted.

A deliberate visual change makes those tests fail with a `.diff.png` beside the baseline. Look at it, then regenerate the baselines with `UPDATE_SNAPSHOTS=1 cargo test` and review the new PNGs in the diff before committing. The `.new.png`, `.diff.png` and `.old.png` files are ignored by git.

### What the tests cover

- `bridge::tests` builds all three payloads for one 2 in square on a 12 x 12 mat. It asserts the `d` string, the transform, the margins, and the pressure arithmetic for Default, More and Less. It also checks mirroring, packed offsets with copies, and the status codes. Golden payloads in `tests/golden/` cover rotated, flipped, mirrored and multi-copy curved designs; they are parsed and compared field by field, and `UPDATE_GOLDEN=1 cargo test golden` rewrites them. Every golden and copies case asserts that each path point lies inside the cutting area, and a corner test checks the mat placement against the canvas for a quarter turn with a flip.
- `composition::tests` checks mat keys and order, attached and packed offsets, row and mat spill, overflow and the operation label.
- `device::tests` drives `SimulatedMachine` through the whole happy path and asserts the `DeviceState` sequence. A table test covers every machine phase and input, including each cancel and the presses the machine ignores, and a killed simulator thread fails both send and receive.
- `make_flow::tests` runs `MakeFlow` against `device::Loopback`, the simulator's machine without its thread. It covers Cancel in Set, Load, Go and Cutting, Pause, Cut more, Rerun after Done and after Cancel, Next Mat after Cancel, a lost machine and a missing remembered machine.
- `design::tests` checks the library paths, insert sizes, outline hit testing and undo history. `ui::canvas::tests` checks the zoom steps and grid multiplier.
- `ui::tests_core` uses `egui_kittest` to click through the real UI headlessly against the simulator. The route is Shapes, Square, Make, Continue, Connect with USB, Continue, Cardstock, More, Next, Load/Unload, Go, Looks good, Unload mat and Back to canvas. `ui::tests_spec09` cuts a two-colour design as two loads with Next Mat between them. `ui::tests_spec35` kills the simulator thread mid-flow and checks for the error and Back to canvas, and types 20 copies into Prepare. `ui::tests_spec22` covers keeping unsaved work without asking (New opens a tab, Home Edit and Make open tabs, closing the window writes the autosave and a clean session), a save into a read-only directory, and an unreadable project's card. `ui::tests_spec33` covers autosave, versions and recovery, and tabs: separate undo, reopening an open project, the tab keys, quitting and relaunching, Restore all and one Make at a time.
- `project::tests` and `sanitise::tests` cover atomic saves, format upgrades, built-ins by name, file-stem ids against a crafted `id`, and the malformed fixtures. `system_fonts::tests` checks that layout changes once a pending catalogue lands and that Make waits for it.

## Editor

The canvas is a direct-manipulation editor. The selection shows one frame: a single shape's own rotated box, or the axis-aligned union of several shapes or a link. It has round corner handles, pill-shaped edge handles, a faint centre cross and a rotate handle, and dragging them resizes or rotates the whole selection as one (Shift keeps aspect while resizing, or frees a locked aspect, and snaps rotation to 15 deg). A multi-selection scales every member's position and size about the opposite handle and turns them all about the frame centre. Below the frame, a size badge shows its width and height in the chosen units, live while resizing, and a floating action bar offers Delete, Duplicate, Attach or Detach and Group or Ungroup (two or more units with no container among them, or a selection already linked), and More (Move to Front, Move to Back, Flip Horizontal, Flip Vertical, Hide). Near the bottom of the canvas they move above the frame. Both hide during a drag and show only with the Select tool. Shift-click adds to the selection and a marquee drag box-selects. Holding Option while you drag a marquee draws a freehand lasso instead: it closes on release and selects every shape with an outline node inside it (a marquee still takes whatever its box touches), Shift adds to the selection, a lasso shorter than 8 px counts as a click and Escape cancels one in progress. The lasso draws as a faint-filled, 1 px dashed accent outline. **Select Same** (the Edit menu, the context menu and the legend pill) picks every visible, unlocked shape that shares the selection's colour, operation, pen, font, shape kind, effects or all of them at once; its All text and All paths rows pick those kinds whatever is selected. A row whose value differs across the selection is greyed, as "Selection has mixed colours", and with nothing selected the whole submenu is greyed. Clicking a legend pill is Select Same by that operation. **Select Inverse** (Cmd+Shift+I) selects every selectable shape that is not selected, and Tab and Shift+Tab walk the selection to the next or previous shape in Layers order. One snapper (`snap.rs`, spec 47) serves every drag. While a move or resize is under way it builds its targets once from the design, the ruler guides and the grid, then finds the one correction that brings a moving point onto a target within the snap distance, preferring the smaller correction and, on a tie, a node over a midpoint over an edge over the grid. The targets are the grid, other shapes' bounding-box edges and centres, their path nodes and segment midpoints, the intersections of straight segments, the ruler guides, and the mat's edges, centre and corners. A move snaps each axis onto a line or the grid and a path node onto another shape's node, so a rotated rectangle's corner meets another shape's corner; the canvas draws today's line at an edge, guide or grid snap, a small cross at a point snap, and tick marks for an equal gap. Equal spacing: a shape dragged between two others on an axis snaps to the same gap on each side. Holding Shift locks a move to the nearer of horizontal, vertical or 45 degrees from the start, shown as a faint ray; it holds a Pen segment to the angle step from the last anchor, a node drag to its own axis or 45 degrees, and a handle to 45 degree steps; Shift while resizing still keeps the aspect, and while rotating still steps 15 degrees. The magnet button by the zoom pill toggles everything on or off, and a chevron beside it (or View > Snapping...) opens a popover with a switch per target class (Grid, Shape edges and centres, Mat, Guides, Nodes and midpoints, Intersections, Equal spacing) and the Shift angle step (15, 30, 45 or 90 degrees). The choices live on `Design::snap` (`SnapOptions`), so the project remembers them; the palette finds each switch, for example "snap nodes". Older projects open with every class on, and files that set a class use format 14. Keyboard: Delete removes, Cmd+A selects all (or, while the selection sits inside one container, that container's children, widening to everything on a second press), Cmd+D duplicates, the arrow keys nudge (Shift for one inch), Cmd+Z / Cmd+Shift+Z undo and redo, Cmd+0 zooms to fit the mat, Cmd+1 shows actual size, Cmd+2 zooms to the selection, Cmd+Shift+0 zooms to all and Cmd+= / Cmd+- zoom in and out. Every shortcut comes from the command table, and the menus print the same keys. While the Pen, Pencil or Text tool or node editing has the keyboard, only Undo and Redo fire. Undo or Redo during a drag ends the drag: the restored design stays put until the pointer is released, and the next drag is an undo step of its own.

**Zoom and view.** View > Zoom to fit (Cmd+0) shows the whole mat with its rulers and a 24 px margin; Actual size (Cmd+1) shows 100 %; Zoom to selection (Cmd+2) fills the view with the selection's frame plus the margin, never closer than 800 %, and is greyed with "Select something to zoom to." while nothing is selected; Zoom to all (Cmd+Shift+0) fits every shape on the canvas, or the mat when it is empty. Zoom In and Zoom Out (Cmd+= and Cmd+-, or the pill's buttons) step about the pointer when it is over the canvas, and about the view centre otherwise; pinch and Cmd+scroll zoom about the pointer. Click the percentage in the zoom pill for the Zoom to menu: 25, 50, 100, 200, 400 and 800 %, then the three fits with their keys. Zooms are not undo steps, and each one glides over 120 ms unless animations are turned off. Two-finger scroll pans, as does a middle-button drag. Hold Space with any tool and the pointer becomes a hand: drag to pan, then let go of Space to carry on, a Pen path in progress included. While a text is being edited Space types a space instead. With nothing selected the arrow keys pan the view (Shift for further); with a selection they nudge. However far you pan, at least 48 px of the mat stays on screen. The maths are in `src/ui/view_nav.rs`, the menu in `src/ui/zoom_menu.rs`.

The edit toolbar is fully live. Flip (horizontal and vertical) mirrors the whole selection across its frame, as the action bar and context menu do. Arrange (Move to Front, Move Forward, Move Backward, Move to Back, the one wording every surface uses), Align and Distribute edit the selection, and the inspector's fields, operation and colour edit it too. A tool is greyed while nothing in its popover can run. Combine opens a grid of tiles: Slice, Weld and Flatten above, Unite, Subtract, Intersect and Exclude below. Combine counts units, where an attached set is one unit and every other shape, group members included, is one each. Weld, Unite, Subtract, Intersect and Exclude (two or more units) and Slice (exactly two units) make a live boolean group at the back-most input's z position, with the inputs kept as its children; see Live groups below. Flatten (two or more objects, or one group) turns the selection into one Print Then Cut shape, `ShapeKind::Flattened` in `flatten.rs`: the canvas still draws each part in its own colour, and the cut outline is the weld of the parts. With one flattened shape selected the tile becomes Unflatten, which puts the parts back where the flattened shape now sits. Whatever Combine makes is selected. Tools that do not fit the window move into an "N More" menu at the right of the toolbar, and each row there opens that tool's usual popover. Contour (a shape with more than one contour) opens a panel where tapping a contour hides or shows it, which also changes Make and the Project Preview. Effects opens a menu of Offset, Sticker and Warp; picking one swaps in its panel, with a back chevron to return. Offset draws an outline at a positive distance shown in the chosen units and stored in inches, outward (Outset) behind the original or inward (Inset) in front of it, with Round, Miter or Bevel corners. Sticker prints the shape on a white backing a border outside its outline (0.125 in by default, round or sharp corners), cut as Print Then Cut. Warp bends each selected shape inside an envelope (Arch, Bulge, Wave, Flag or Rise, with a bend from -100 to 100, horizontal or vertical), and the shape's frame refits to hug the bent outline; Remove Warp restores the original outline and size. Upload imports an SVG at true scale from its `width`, `height` and `viewBox`. A filled path keeps its fill colour; a gradient or pattern fill keeps the fill's mean colour; a path with a stroke and no fill becomes a Pen line in the nearest of the 24 pens by colour, at the pen size nearest the stroke width. A thin stroke (under 0.01 in) or a black stroke on a closed path with no fill is a cut line by laser and Inkscape convention, so it imports as Basic Cut and a notice offers **Treat hairlines as** Cut, Pen or Score, applied to every imported stroke in one undo step (Cut by default when every stroke is a hairline). What was lost is counted and named in the notice: gradients reduced to their mean colour, strokes dropped from filled shapes, fills faded below full opacity (they still cut at full strength), dash arrays, and invisible paths that had neither fill nor stroke. Each `<g>` becomes a Kerf container holding its children, nested as the file nests and named by its SVG `id`, and every path with an `id` keeps it as its layer name; a group of one path collapses to the path. When strokes came in, the notice also offers **Outline strokes**, which expands each imported stroke to a filled ring at its own width for artwork that relies on thick outlines. It also takes a PNG, JPG or WebP image; see Images.

**Live effects.** Every effect stays editable on its layer (`src/effects/`). Warp, Offset and Sticker are entries in an ordered stack on the shape, each with a stable id, evaluated into styled pieces whenever the shape is drawn, hit, composed, previewed, exported or cut; text Curve and hidden contours are source settings listed with them. Moving, resizing, editing nodes or retyping the text updates the Offset ring and the Sticker backing live. An Offset is its own piece, behind the shape (an Inset in front of it), cut in the layer's operation and colour, and packed on the mat with its source. A Sticker piece is Print Then Cut whatever the layer's operation, so Make loads a blade and sends a fiducial. The Effects panel holds an Offset or Sticker as a draft until Apply; with one object selected it then edits that entry live, and typed values commit on Enter, so each change is one undo step. With Weld offsets on, an Offset over several objects, and a Sticker over several, make an effect group; see Live groups below. In Layers a row with effects shows chips under its name (three, then +N); hovering one shows its settings, and clicking one opens its panel beside the row, filled with what is stored. The disclosure after the chips lists every effect under the row, each with an eye that turns it off without losing it, Edit and remove; stack entries drag to reorder, so a Warp moved above an Offset bends the ring too. The inspector lists the same under Applied effects. Expand (context menu, command palette) bakes the selection's effects into plain shapes, exactly as the destructive actions made them: each Offset becomes a shape behind the source, a Sticker becomes the flattened sticker, and a warped body becomes a path. Flatten refuses a live Offset or Sticker until it is expanded, and text with effects does not split into letters. Editing a warped path's nodes says the first edit applies the warp, and that edit bakes it in the same undo step; a Warp after an Offset or Sticker cannot be node-edited until expanded. Every destructive operation consumes what Delete would delete, so a container's children go into the result rather than being left behind.

**Live groups.** Combine and Slice no longer bake their inputs. They make a boolean group (a `ShapeKind::Compound` in `src/effects/compound.rs`) whose children are the inputs, kept intact and editable, and whose outline is the boolean of them, evaluated live like any effect. Slice gives its three pieces while the group holds exactly two units of children, and draws them as they are otherwise. A welded Offset or a Sticker over several objects makes an effect group in the same way: the children draw as themselves and the group's own Offset or Sticker goes round them all. In Layers a group lists like a container, its children indented under it, top first. A boolean group's row carries its operation's icon in a small dropdown that lists the six operations with the current one ticked; picking another changes the group in one undo step, and one its children cannot take (Slice with other than two) is greyed with the reason. Dragging a Layers row onto a group or between its children adds it as an input, and dragging a child out removes it; the group refits round its children either way. On the canvas a click selects the whole group, and Cmd-click selects the child under the pointer, even inside a Subtract hole, so dragging it moves just that child while the group re-evaluates. Moving, resizing, rotating or flipping a group carries its children with it, and typing a size reads back exactly. A group cannot be warped or node-edited. Expand bakes a group one level: a boolean group becomes the plain shapes its result makes, exactly as Combine and Slice made them before, and an effect group releases its children and bakes its own Offset or Sticker as Expand does for one shape. Projects with groups use format 7.

Group (Cmd+G) and Attach (Option+A) tie two or more selected objects together (a link already selected counts as one, and a container cannot be linked, so both are greyed for a container and a shape); Ungroup (Cmd+Shift+G) and Detach (Option+Shift+A) remove them. All four sit in the Edit menu. Clicking, dragging or marquee-selecting any member selects the whole link, and moving it moves every member. Cmd+click picks one member on its own; the next plain click selects the whole link again. Group only ties shapes together on the canvas, while Attach also keeps their relative positions on the mat. Linking pulls shapes out of any earlier link and gathers them in the z-order at the top-most member's slot, and Arrange then moves a link as one block. Duplicating a link gives the copies their own new link, and deleting or combining members down to one dissolves it. In the Layers panel a link is a parent row named Group or Attached, with its members indented beneath; the parent selects, hides or deletes every member, and its chevron collapses the list. The link is stored on each shape (`Shape::link`, see `links.rs`), so projects saved before links still load.

A fixed action bar sits at the foot of the inspector, under the Layers list, so the common layer operations are next to the list where objects are picked: Slice (exactly two units), Combine (two or more units, opening the Combine tiles above the bar), Attach (two or more units), Flatten and Contour (one shape with more than one contour). Attach turns into Detach for an attached selection, and Flatten into Unflatten for a flattened shape. Disabled buttons stay grey and keep their tooltips, which open above the bar. The Layers list scrolls above the bar, so the bar stays visible however many layers there are. The bar is `src/ui/layers_actions.rs`.

The Layers list is a selection surface, like the canvas. Clicking a row selects that object: a parent row selects the whole Group or Attach, and a member row selects that member alone. Shift-click selects every row between the last clicked row and this one, and Cmd-click adds or removes one row. Selected rows are tinted with the accent wash, and the canvas frame follows in the same frame. A row's eye, arrows and bin act on that row without changing the selection. Selecting on the canvas scrolls the first selected row into view.

**Names.** A name too long for its row stops short of the row's icons and ends in an ellipsis, on every row kind and in the effect list; resting the pointer on a cut-short name shows it whole. Any layer can be renamed: double-click its name in Layers, choose Rename in the context menu or the command palette, or press F2 or Enter with one layer, or one whole Group or Attach, selected. The name opens for typing with its text selected. Enter or a click elsewhere commits it as one undo step, Escape cancels, and a blank name gives the layer back its label (Octagon, Group, Subtract). Group and Attach parent rows, containers and live groups rename the same way, and a duplicated or detached group keeps its name. Export names layers and Attach groups by these names. A shape's name is `Shape::name`, a link's lives in `Design::link_names`, and the rules are in `src/names.rs`; the row text and the rename field are `src/ui/names.rs`. Projects with names use format 11.

Layers rows can be dragged. Press a row and move it a few pixels to pick it up: a selected row brings the whole selection with it in its current order, an unselected row comes alone and is selected when it lands, and a parent row brings its whole Group or Attach. A translucent copy of the row follows the pointer, with a count when more than one object moves. A violet line shows where the objects will land, indented when the drop is among a link's members, and hovering the middle of a parent row highlights it to drop inside. Dropping between rows sets the z-order. Dropping among a link's members, or on its parent row (at the top of its members), adds the objects to that link. Dropping between top-level rows takes them out of any link, except a link dragged whole, which moves as a block; a link left with one member dissolves as Ungroup does. A link cannot be dropped into itself, and the pointer shows not-allowed there. Near the top or bottom edge the list scrolls. Escape or releasing outside the list cancels. The canvas follows in the same frame, and each drop is one undo step. The drop rules are pure functions in `src/layers_dnd.rs`; the panel side is `src/ui/layers_panel/drag.rs`.

Right-click (or Ctrl-click on macOS) opens a context menu. Over a shape it first selects the shape, or its whole link, unless it is already selected, so the menu acts on the full selection. The menu holds Rename, Duplicate, Cut, Copy, Paste and Delete, Group or Ungroup, Attach or Detach, Make container (Wrap in container for two or more) and Remove container, a Combine submenu, Flatten or Unflatten, Arrange, Flip and Align submenus, Hide and Select All. Shortcuts are shown on the right, and items that cannot apply are greyed by the same check every surface uses. Right-clicking a Layers row opens the same menu for that row's object. Right-clicking empty canvas offers Paste, Select All and Deselect. Escape, a click elsewhere or picking an item closes the menu. Design changes take one undo step. The menu table is `src/ui/context_menu.rs`; its rows use the command table, and design edits run through `edit::run`.

**Clipboard.** Cmd+C copies the selection. If a Measure label is visible, Cmd+C copies that label instead. Cmd+X copies the unlocked selection and removes it in one undo step; locked layers stay. Cmd+V offsets a copy by 0.25 in when you paste into the same tab, pastes in place in another tab with the same mat size, and centres it on the view when the mat sizes differ. Cmd+Shift+V always pastes in place. Cmd+Option+V applies the first copied shape's operation, colour, pen and pattern to the selection without changing its geometry. **Copy as PNG** (the Edit menu, the context menu and the command palette) renders the selection at 300 dpi with a transparent background and puts the picture on the system clipboard beside the vector clip, where the platform allows an image, so a paste into a chat gets the picture and a paste into Kerf gets the shapes.

Kerf writes one Filled-style SVG to the system clipboard. It carries a native package in an SVG metadata element, so Kerf keeps groups, containers, components, link names and image assets when you paste it back. The same SVG gives other vector editors editable paths. Pasting an external SVG imports its paths at true scale. Pasting plain text creates a text shape at the view centre. The current eframe clipboard input is text-only; use Upload to trace an image file. The clipboard adapter is `src/ui/clipboard.rs`; package closure, validation and id remapping are in `src/clipboard.rs`.

**Guides.** Press on a ruler and drag onto the artboard to pull out a guide: the top ruler gives a horizontal guide, the left ruler a vertical one. It follows the pointer, snapping to the grid, shape edges and centres and the other guides while magnetic snap is on, with its position in the current units beside the pointer, and lands on release. Releasing back over the ruler, or off the artboard, places nothing. A guide spans the whole artboard as a thin violet line above the shapes and below the selection frame. With the Select tool, hovering a guide shows a resize cursor and an accent marker on the ruler; drag it to move it, or drag it back onto its ruler to delete it. Double-click a guide to type its position, as any calculation a length field takes (`1in + 5mm`), lock it or delete it; right-click it for the same plus Lock all guides and Clear guides. Right-click the rulers or their corner for Show guides, Lock guides and Clear guides, which View also lists: Show guides is Cmd+; and Lock guides Cmd+Option+;. A locked guide cannot be grabbed and a click passes through it to the shape beneath; unlocking all guides also frees any guide locked on its own. Hidden guides neither draw nor snap. Guides are never shapes: they never select, never appear in Layers, and Make, the mat previews, export, thumbnails, Flatten and Combine never see them. While a move or resize snaps to a guide, the guide lights at full accent. Pen anchors snap to guides too. Every guide change, a whole drag included, is one undo step. Guides belong to the project (`Design::guides`, with `guides_locked` and `guides_hidden`), so they save, autosave and version with it; projects with guides use format 12, and older projects open with none.

The Align popover is a two-column grid: Top, Vertical, Bottom and Centre on the left, Left, Horizontal and Right on the right, with Distribute Vertical and Horizontal below a divider. Each button's tooltip says what moves. Centre stacks every centre on one point as one undo step. A group or attach set counts as one unit: it is measured by the union of its members' bounds and every member moves by the same amount. Align needs two units and Distribute three; buttons needing more stay visible but disabled, and their tooltip names the count. The Align to choice is part of the Align edit, remembered on the canvas view rather than in egui memory.

### Shape parameters

The free shapes are live. A rectangle keeps its corner radii, a polygon its side count, a star its points and inner radius, an arc its angles, after it is placed, so you never need a new library entry or an Offset trick to round a corner or add a point. Each is a `ShapeKind::Parametric` whose `Params` the one generator in `parametric.rs` draws, and the Shapes panel and command palette place the preset that reproduces the shape you picked. Rectangle, Square, Rounded Square, Pill and the Arch become rectangles with per-corner radii; Triangle, Diamond, Pentagon, Hexagon and Octagon become polygons; Star and Thin Star become stars; Circle and Oval become ellipses; the Half Circle, the Plus and the Line become an arc, a plus and a line. Heart, Equals and the procedural built-ins keep their fixed outline.

When every selected shape is the same kind, a **Shape** section appears under Size in the inspector, with one field per parameter: a count for sides and points, a length for corner radii, a percentage for a star's inner radius or a ring's width, degrees for an arc's angles, and a Link toggle and a Scale with shape toggle for a rectangle's corners. A typed value applies to all, mixed values show blank, and each commit is one undo step. On the canvas a selected rectangle shows a small diamond handle at each corner; drag one inward and the corners round, with the radius read out beside the pointer. The handles hide during a drag and never show on a multi-selection. Corner radii are kept in inches, so a resize leaves them be unless Scale with shape is on, when they track the width.

Double-clicking a parametric shape or pressing A offers node editing, which turns it into a `Path` of its outline in the same undo step, after a notice that its parameters are lost; one Undo brings the shape and its Shape section back. Combine, Offset, Warp, Flatten and Make read the outline and need no change. Projects saved before this feature upgrade on open, each old kind becoming the preset that draws the same outline within the 0.01 in flatten tolerance.

### Colour, swatches and Replace colour

The Colour field opens a swatch picker (`src/ui/colour_picker.rs`) in place of a bare colour wheel, wherever a solid colour is chosen: the inspector swatch, the pattern panel's colour tab and an instance's part overrides. Top to bottom it shows a hex field that takes `#RGB`, `#RRGGBB`, a bare `RRGGBB` or a CSS colour name such as `rebeccapurple` on Enter, with a message when the text does not parse; the hue, saturation and value area; **Project colours**, every distinct colour already in the design as a swatch with its shape count on hover, so picking one makes no new mat, with a Pen layer's colour counted apart from a fill of the same value; **Recent**, the last twelve colours chosen in any project; and **Saved**, your own swatches. The + adds the current colour to Saved, right-click a saved swatch to rename or delete it, and the dropdown adds a whole bundled palette (Vinyl, Iron-On, Cardstock basics, Pastel, Earth or Mono, colour lists in `src/palettes.rs`). Clicking any swatch applies it to the whole selection in one undo step, as the field always has. On a Pen layer the field still shows the pen list. Recent colours and saved swatches live in `settings.json`, so they span projects; the hex and CSS parsing and the project-colour counts are pure in `src/palettes.rs`.

**Replace colour** (the Edit menu and the command palette) swaps one of the design's colours for another across every shape that has it, in one undo step. It lists the fill colours with their counts, you pick one and type the replacement, and Replace recolours every shape with that fill, leaving pens and patterns alone. It is Select Same Colour then a swatch click (see Select Same above) packaged for the common "make all the dark blue navy".

**Eyedropper.** The Eyedropper tool (left rail, key I) lifts a shape's whole style. Click an object to copy its operation, fill, pen and pattern; with a selection the click applies that style to the selection, Shift-click applies it to the clicked shape, and Option lifts the colour alone. The pointer shows a dropper and a swatch of the colour beneath it, read from a decoded image or pattern so a colour can be sampled from a photo (`src/ui/eyedropper.rs`). Save palette to project and Copy palette to settings (the Edit menu) move swatches between the project and your settings; a project keeps its own swatches in `Design::swatches`, and saved swatches drag to reorder in the picker.

### Command palette

Cmd+K (or View > Command palette) opens a search box near the top of the canvas, over everything. It finds and runs anything by keyboard. Cmd+K again, Escape or a click outside closes it.

It searches four sources. Commands are every row of `commands::registry`: the File, Edit, View and Help menu items, the toolbar and action-bar actions, Combine, Align, Arrange, Flip, Offset, Sticker, Warp and Remove Warp, Hide and Show, the four nudges, a Set colour row for each pen colour, zoom, units, magnetic snap and the partial grid. Shapes are every Shapes panel shape, and picking one inserts it in the next free slot, selected. Fonts are the bundled and system fonts: with text selected a font sets it, otherwise it places a new text in that font. Recent projects are the 10 most recently saved, and picking one opens it in a tab, or shows its tab when it is already open. On Home the palette lists only what works without the canvas: New, the tab commands, the projects and the units.

The palette has no commands of its own. Each row is resolved through the same `Cx` and `Design::check` as every other surface, so a row greyed in the toolbar is greyed here, with the reason on a second line. Enter on a disabled row does nothing and highlights the reason. A pick runs through the app's one command path before `History::observe`, so it is one undo step.

Up and Down move, Enter runs and closes, and Cmd+Enter runs and stays open, which suits nudges and toggles. Page Up and Page Down jump by section. Each row shows its icon, label, source and shortcut, and the list renders at most 50 rows and scrolls.

Matching is a fuzzy subsequence match over the label and a few aliases ("color" finds the colour rows, "remove" finds Delete, "weld" also finds Unite). Case, accents and spaces in the query are ignored. Consecutive letters, word starts and a match at the start of the label score higher. Commands run from the palette get a small boost that halves every three days and is capped, so a command you use often rises above an equally good match but never above a better one. With an empty query the palette lists Recent (the last 8 rows run from it, newest first), then Suggested (what the selection makes possible, such as Group, Attach, Weld and Align for two shapes). Runs are kept in `settings.json` as `palette_recent`, newest first and capped at 50. The matcher is `src/palette/fuzzy.rs`, ranking and recents are `src/palette/mod.rs`, and the overlay is `src/ui/palette.rs`.

### Help and the tutorial

The Help menu, after View in the top bar, holds **Interactive tutorial**, **Keyboard shortcuts** and **About Kerf**. Keyboard shortcuts opens the command palette listing only commands that have a shortcut. About Kerf shows the version. The palette also has **Start tutorial**.

The tutorial never starts by itself; it runs only when you choose it. It opens a **Tutorial** tab holding a sample card (a heart, a line of text and a star) and walks through Kerf in 40 short steps, from Home to the canvas tools, editing, operations, text, arrange, effects, combine, nodes, components, patterns, the palette, Make, Export and saving. Each step dims the window and cuts a rounded hole around what it describes, with a card beside it naming the section, "Step 7 of 40", the shortcut where there is one, and Back and Next. Clicks inside the hole reach the app and clicks on the dim do nothing, and the keyboard keeps working. Steps that ask you to do something (open Shapes, add a shape, select the heart, outline the text, subtract the heart from the card, edit the star's points, make a component, open the palette, start Make) move on when you do it; **Show me** does it for you through the same commands the menus run. Escape, the close button or **Skip tutorial** ends the tour at once, closes the Tutorial tab and returns to the screen and tab you started from. The Tutorial tab is transient: it never saves, autosaves or appears in the next session. The steps are data in `src/ui/tutorial.rs`; widgets record where they draw with `ui::anchors::mark`, and `src/ui/tutorial_overlay.rs` draws the dim layer, cut-out and card.

### Containers

Any shape can be a container that holds other objects: a heart, a circle, a card rectangle, a text or a Guide frame. With one shape selected, Make container (Cmd+Option+G, in the Edit menu and the context menu) gives it the container role and selects it. With two or more selected the same command reads Wrap in container: it draws a Guide rectangle around them with 0.25 in of padding, makes them its children and selects it. Remove container clears the role and leaves the shape and its children where they are. Drag an object onto a container and it becomes a child, with a dashed violet frame on the target's padded box while the pointer is over it; drag a child out past the container's edges and it leaves. Hold Cmd while dragging to move without dropping in or out. Where containers overlap, the front-most one under the pointer wins. A container may hold links and other containers. Moving, rotating or deleting a container moves, rotates or deletes everything inside it. A selected container shows the same dashed frame. In Layers a container is a parent row with a small dashed badge before its name and its children indented beneath, at any depth; dragging rows onto a container row, between its children or out to the top level moves objects in and out. A Guide container that holds objects stays selectable with a marquee.

While the selection sits in one container, or the container itself is selected, the Align popover gains an Align to toggle: Selection or Container, with Container the default. With Container, Align lines objects up on the container's padded edges and centre, so one star can be centred on a heart, and Distribute spaces them from the left padding edge to the right one, needing two objects rather than three. Selecting the container alone and choosing Align acts on all its children. The context menu's Align rows follow the same choice.

The inspector's Container section, shown when one container is selected, sets Padding and Layout: None, Row, Column, Grid or Radial. With a layout the container places its children itself, in Layers order, every time they change: Gap sets the space between them, Align items places each on the cross axis (Start, Centre or End), Size either hugs the children plus padding or keeps a fixed size and spreads them across it, and Grid adds a column count. Radial rings the children round the container's centre instead, with Radius, Start angle, Sweep and a Rotate items toggle that turns each child to face outward; a full 360 degree sweep divides evenly so the first and last do not land together, a partial arc puts one child at each end. Children of a laid-out container cannot be dragged into place; dragging one reorders it, and a newly dropped child joins at the end. The model and the pure layout are `src/containers.rs`; the canvas side is `src/ui/container_canvas.rs` and the inspector section `src/ui/container_panel.rs`.

### Repeat and transform

Duplicate (Cmd+D) copies the selection a quarter inch down and right. Move, rotate, resize or flip that copy and press Cmd+D again and the next copy repeats the same step from where the copy sits now, so Cmd+D, move, Cmd+D, Cmd+D lays out a row at an even pitch: this is Power Duplicate. The step is the transform between where the copy's source sat and where the copy sits now, kept on the document as a `DuplicateMemory` and dropped when the selection becomes something other than those copies. Transform Again (Cmd+Shift+D) applies the last transform to the selection again without a copy; a move, resize, rotate or shear gesture on the canvas records a step too, so Cmd+Shift+D repeats it while Cmd+D stays a plain Duplicate. A pivot in the step, such as a rotation about a corner, is preserved, so each repeat swings round the same point, and a repeated shear or flip carries as well. The step maths is pure in `src/repeat.rs` and `src/transform.rs`.

Step and repeat and Rotate copies, in the context menu, open a popover with a live preview of the copies in faint accent outlines. Step and repeat takes Copies, Offset X and Y, a Rotation step, a Scale percent and a Grid toggle that adds Columns and a second offset; Apply makes the copies as plain shapes grouped with the source in one undo step, and Cancel or Escape makes nothing. Rotate copies takes Copies and a Total angle and rings the copies about the pivot (the selection's pivot, or its frame centre), grouped; twelve copies over 360 degrees sit at 30 degree steps. A container's Radial layout is the live alternative, where the children stay editable and a change to one does not break the ring. The popover is `src/ui/repeat_panel.rs`.

A shape's pivot is the point rotation turns about: canvas rotation, the typed Rotation in the inspector and Rotate copies all turn about it rather than the shape's centre. With one object selected, the centre crosshair is draggable; dropping it sets the pivot, snapping to the frame's corners, edge midpoints, centre and to spec 47's snap targets, and a double-click resets it to the centre (`src/ui/pivot.rs`). A pivot saves with the shape; a project saved before this feature loads with none, meaning the centre. Skew leans a shape along its own X or Y axis, from -89 to 89 degrees, set by the inspector's Skew X and Skew Y fields or by Cmd-dragging a side handle, which shears instead of resizing; the selection frame then draws as a parallelogram with its handles on it. Skew is applied between scale and rotation in the one placement matrix (`src/effects/eval.rs`), so everything that reads an outline, including the canvas, Combine, Offset, Make and export, sees the sheared shape with no change of its own, and the stored width and height are unchanged. A 30 degree Skew X slides the top edge by the height times the tangent of 30 degrees and keeps the area the same.

The geometry lives in pure, unit-tested modules: `transform.rs` (the selection frame, its handles, and multi-shape resize, rotate and flip), `snap.rs` (snapping) and `geometry.rs` (flatten any shape to inch-space rings with a 0.01 in tolerance, rebuild paths, triangulate with holes, and run boolean and offset ops). SVG import is `shape_library::import_svg`. Dependencies: `rfd` (file dialog), `i_overlay` 9 (boolean ops, non-zero fill rule), `earcutr` (hole-aware triangulation), `directories` (app-data paths), `tiny-skia` (thumbnail rasterising), `image` (PNG for thumbnails, and the pure-Rust PNG, JPEG and WebP decoders for uploads; MIT or Apache-2.0), `blake3` (asset hashes, built with its `pure` feature so no C or assembly; CC0-1.0 or Apache-2.0), `visioncortex` (image tracing; MIT OR Apache-2.0), `serde` (project JSON), plus `egui_extras`/`usvg` for SVG. Offset uses `i_overlay`'s own outline offset and its Round, Miter and Bevel joins, so no separate offset crate is needed.

### Components

A component is a reusable part of a design, such as the frame of a favour tag that repeats forty times. Select shapes and choose Make component (Cmd+Option+K, in the Edit menu and the context menu): they move into a new component named "Component 1", and one instance of it takes their place, selected. Undo puts the shapes back. The component's master keeps the shapes; an instance only places it, so changing the master changes every instance. An instance is a shape like any other: move, resize, rotate, flip, group, attach, lock or give it effects, and its parts follow as one rigid unit. In Layers an instance is a parent row with a component badge, its parts listed beneath as read-only rows; clicking a part row selects the instance.

The **Components** tab beside Layers shows each component as a thumbnail with its name. Click a tile's picture to place an instance at the master's size, or drag the tile onto the canvas to place one where you let go. Double-click a tile's name to rename it in place, in one undo step; a long name ends in an ellipsis and shows whole in the tile's tooltip. Right-click a tile to Rename it, Edit master, Duplicate component or Delete it. Deleting a component that has instances asks first: **Detach N instances and delete** turns them into plain shapes, and Cancel keeps everything. A component can hold instances of other components, but never itself, directly or through another; Kerf refuses with "A component can't contain itself."

**Editing a master.** Double-click an instance, or choose Edit master on its tile, to open the master on its own: the canvas shows only its shapes on an artboard the size of the component, under a breadcrumb "Canvas > Component: Name" with **Done**. A strip along the bottom draws every instance on the canvas live, so each change shows where it lands. Every tool works there: nodes, text, Combine, effects, colours and operations. Each change is an ordinary undo step in the same history as the canvas, so Undo after Done reverts master edits too; opening a master and Done are not undo steps. If an Undo takes the component away, the master closes by itself. Commands that act on the whole project (Make, Preview, Export, Home) close the master first.

**Overrides.** With one instance selected, the inspector's **Parts** section lists its parts, each with its colour swatch and operation. Change a part's colour, operation, pattern (on a Print Then Cut part) or pen (on a Pen part) and only that instance changes; a small violet dot marks each overridden part. **Reset overrides** makes every part match the master again, and right-clicking a part row offers **Reset this part**. Deleting a master shape drops its overrides from every instance. Size, rotation, flips and effects on the instance are its own frame, not overrides.

**Detach.** Detach instance (Cmd+Option+Shift+K, in the context menu) replaces an instance with plain shapes equal to what it drew, overrides included, grouped at the instance's place in Layers and selected. In Make each instance is one rigid unit per mat: a two-colour component spreads its parts over two mats, each colour keeping its layout. Projects saved before components open with none, and an instance whose component is missing from a hand-edited file draws as a "Missing component" box. The model is `src/components.rs`; the panel is `src/ui/components_panel.rs`, isolation `src/ui/component_isolation.rs` and the Parts section `src/ui/instance_overrides.rs`.

### Monograms

The **Monogram** item on the tool rail, below Shapes, opens the Monogram panel in the Shapes panel's place. Type one to three letters (any characters; spaces are ignored), then pick a **Theme**: Classic, Modern, Script, Sports or Botanical. A theme sets the style, the frame and the fonts at once; change any of those afterwards and the theme reads "Custom", while everything else stays. The large preview above the controls redraws on every change and never touches the canvas.

The **Style** tiles are drawn with your letters. Single is one large initial. Classic three takes the letters in the traditional order First, Last, Middle and sets the last name's initial in the centre, with the other two at 70 % beside it. Even three sets three letters at one size. Stacked sets two or three in a column. Interlocking overlaps two or three by a fixed share of their width, ready to weld. Circle sets the centre letter large and curves the first and middle letters round it as one line of curved text, which stays editable like any curved text. The help line under Letters says what each style expects.

The **Frame** tiles are None, Circle, Double circle, Square, Diamond, Scalloped circle, Laurel, Shield, Banner and Leaf wreath. Frames are original artwork in `assets/monogram/frames/`: each SVG marks the region its letters fit in, draws its main outlines as centrelines that the Thickness setting turns into bands, and draws leaves, tails and other decoration as filled shapes. The frame grows to fit the letters with the padding you set.

**Fonts** has a picker per role, centre and sides, listing Kerf's fonts, the installed families and the writing fonts. Kerf bundles DM Serif Display, Great Vibes and Oswald Bold for the themes, so a monogram looks the same on every machine. When a font has no glyph for a letter, Kerf sets that letter in Inter and says so under the preview, for example "Great Vibes has no 'Ж'. Kerf used Inter for it." **Adjust** sets the letter spacing, the centre letter's size, the frame padding and the frame thickness, each with a slider and a typed length in the current units.

**Output** chooses what the monogram is made of. Layered keeps the frame and each letter as separate shapes. Knockout cuts the letters out of a solid frame. Welded joins the frame and letters into one outline that cuts as one path. Knockout and Welded are live boolean groups, so the letters stay editable underneath. **Operation** is Basic Cut, Pen or Print Then Cut. Pen sets every font that has a writing font in it (the themes' fonts all do) and keeps the output Layered, since a pen draws lines rather than areas.

**Insert** adds the monogram at the centre of the view in one undo step and selects it. It is one group named "Monogram ABC" that keeps its settings. Double-click it, or choose **Edit monogram** from its context menu or the command palette, to reopen the panel on it; **Update** lays it out again in place, keeping its position, rotation and flips and fitting its old size, as one undo step. Moving, sizing, turning or recolouring the group keeps it editable. Ungrouping it (Cmd+Shift+G) leaves plain shapes, and editing one of its frame or letters directly makes Edit monogram unavailable with "This group was edited by hand." A monogram can become a component like any group. Projects saved before monograms open unchanged. The layout is `src/monogram.rs`, the themes `assets/monogram/themes.json` and the panel `src/ui/monogram_panel.rs`.

### Pens

A Pen layer's colour is a physical pen. When every selected shape uses the Pen operation, the Colour swatch shows the pen's name and opens a pen picker instead of the RGB picker. The picker has a size dropdown (Extra Fine 0.3mm, Fine 0.4mm, Medium 1.0mm, Bold 2.0mm) above a scrolling list of 24 named pen colours from `src/pens.rs`. Picking a pen sets it on every selected shape and repaints the shape in the pen's colour, so the canvas, Layers, the Project Preview and the payload's `pathColor` all agree. A shape switched to Pen takes the pen colour nearest its current fill. Open Pen paths draw at the nib width for the current zoom, never thinner than 1px. In Make, the Load step lists one line per distinct pen size and colour, grouped under the Pen operation in layer order, for example "Load Black Fine Point Pen in Clamp A". Projects saved before pens existed load with a Black Fine Point pen.

### Operation rendering

Every operation has its own look on the canvas, so you can tell at a glance what will be cut, drawn, scored or printed. The styles are set out in section 9 of `docs/evidence-ui.md`. Basic Cut fills in the layer colour. Wavy Cut fills and draws its edge as a small wave. Perforate draws 15 on 5 dashes and Score 20 on 20 dashes, both without fill. Pen draws at the nib width in the pen colour. Foil draws a 1, 2 or 3 pt line with a metallic sheen. Deboss draws a 3 pt groove and Engrave a fine solid line. Print Then Cut shows the printed fill with a thin cut line and a faint shadow, like a sticker. A Guide is a faint dashed line that a marquee passes over, though a click still selects it. Dashes, waves and tool widths are screen points, so they look the same at every zoom; only the pen nib follows the zoom. The Project Preview and Prepare mats use the same styles, and a shape the same colour as its mat gets a black or white outline.

Kerf adds three cues of its own. A legend pill beside the zoom pill lists the operations in the design with a swatch of each; clicking one selects every shape with that operation, and when there are too many to name it shows swatches only, each named by its tooltip. Each Layers row shows its operation's icon (cut, draw, print or guide) next to the colour dot. Resting the pointer on an unselected shape for half a second shows its operation, and the material once a Make flow has chosen one, for example "Basic Cut, Cardstock". View > Show as made draws everything as the machine will make it: cuts as outlines only, pens and foil as lines, scores dashed, prints as prints, and no guides. The rendering table is `src/ui/op_style.rs`; the legend, hint and toggle are `src/ui/op_legend.rs`.

### Precision

**Expression fields.** Every number field (X, Y, W, H, Rotation, Offset distance, Sticker border, Diameter, padding, gap, spacing, device lengths and more) takes a calculation as well as a number. Type `2in + 5mm`, `(12 - 0.5) / 3` or `30cm - 2 * 1in`, then press Enter or click away. Units `in`, `"`, `ft`, `mm`, `cm`, `m` and `pt` mix freely, and a bare number is in the current units. Start with `*` or `/` to scale what is there: `*2` doubles, `/3` divides, and with several shapes selected each one scales its own value. Start with `=` to type a fresh value. If the field cannot read what you typed, it turns red, says where it stopped (for example "Expected a number at character 6") and keeps the old value; fix it, or press Escape to cancel. Angles, counts and percentages take the same calculations without units. Each committed value is one undo step. `src/expr.rs` is the parser, `units::length_field` the one widget, and a scan test in `units.rs` fails if any other file builds a numeric `DragValue` or a length `TextEdit`.

**Inset and corners.** Offset grows a shape outward (Outset) or shrinks it inward (Inset); the distance is always positive. Corners are Round, Miter or Bevel; Miter has a limit (default 4) past which a sharp point is cut off. An inset sits in front of its shape. Parts narrower than twice the inset vanish, and the Offset panel says "Some parts are too thin for this inset"; if nothing is left, the Offset stays in the list, adds nothing, and its row looks turned off until you lower the distance. Projects saved with a signed distance and Round or Sharp corners load as Outset or Inset with Round or Miter corners.

**Pattern fill.** A Print Then Cut shape can print an image or a repeating pattern instead of its flat colour. Click the Colour swatch and pick the **Pattern** tab, which only Print Then Cut shapes offer (an uploaded image or a flattened shape keeps its own picture). It holds six bundled patterns (stripes, dots, checks, gingham, chevrons and stars) in four colourways, drawn by code so each tile repeats seamlessly, and **Upload image**, which takes a PNG, JPG or WebP through the same decoder and asset store as Upload. Below them sit the pattern's settings: **Tile** repeats it, with the tile width as a length; **Fit** shows the whole image inside the shape, **Fill** covers the shape with it and **Stretch** stretches it to the shape's box, each with a percentage scale. Rotation turns it about the shape's centre, and X and Y offset it. **Remove pattern** prints the colour again; the colour still picks the shape's mat. The swatch shows the pattern while one is set. Turn on **Edit pattern** under the swatch to drag the pattern inside the shape, scale it from the frame's corner handle and turn it from the handle above, while the shape stays put; Escape or a click outside the shape leaves it. Every change, a whole drag included, is one undo step. The pattern is print artwork, so the canvas, the mat previews, the Print step, the print sheet, thumbnails, Sticker, Flatten and export all show it, clipped to the shape. Projects saved before pattern fill open with none.

**Measure tool and live distances.** Pick Measure on the tool rail (M) and drag between two points. Each end snaps to path nodes, edges, shape centres and the mat's corners, centre and edges while magnetic snap is on. The label shows the distance, its horizontal and vertical spans and the angle (0 degrees to the right, counterclockwise positive), all in the current units. Hold Shift to keep to 45 degree steps. The measurement stays until Escape, the next drag or another tool; Cmd+C copies its text. While you move a shape, a read-out beside the pointer shows how far it has moved; while you resize, it shows the new width and height. Hold Option with a shape selected and point at another to see red distance lines from the selection's edges to that shape's edges, as in Figma. Measuring never changes the design or the undo history.

**Locks.** Each object can lock its aspect, its position or its layer. The chain between W and H locks the aspect: typing a width changes the height in proportion, and the side handles scale both sides; hold Shift during a drag to do the opposite. The padlock beside Rotation locks the position: the object keeps its place and size, its handles disappear, and nudges, drags, flips and typed positions leave it alone. It can still be selected and recoloured, its operation changed and its text edited. Align and Distribute leave a position-locked object where it is and line the others up against it. The lock on a Layers row locks the layer: the canvas no longer selects it by click, marquee or Select All, so a click passes through to whatever lies beneath, while its Layers row still selects it. Locking a group, link or container row locks everything in it. Each lock change is one undo step, and projects saved before locks open with nothing locked.

## Drawing tools

The left rail has a Tools group (Select, Pen, Pencil, Text, Measure, Corner, Shape Builder, Knife; keys V, P, N, T, M, C, Shift+M, K). The Pencil captures freehand pointer motion, simplifies it with Ramer-Douglas-Peucker (0.02 in tolerance) and fits a smooth Catmull-Rom cubic path. The Pen places a Straight node on click and a Symmetric node on click-drag (hold Option while dragging to break the handle into a Cusp, so only the outgoing handle follows), with a live rubber-band preview; clicking the first anchor or pressing Enter or double-clicking finishes (closing on the first anchor, open otherwise). Hovering the first anchor rings it and snaps the rubber band to it, and a press there closes the path even if the mouse moves a little, Escape cancels, Backspace removes the last anchor. Both produce a `ShapeKind::Path { contours, view_box }` shape with the Pen draw operation; open paths emit a `d` without a closing `Z`, carry their stroke colour as `pathColor`, and join the mat of a cut shape they are attached to, or a mat of their own colour. Drawn paths are ordinary shapes afterwards: move, resize, rotate, recolour, delete, undo, and Combine/Offset/Contour (beziers flatten to the polyline contour for booleans). Double-clicking a drawn path or any other shape outline with Select, or pressing A with it selected, edits its nodes; see Node editing below. Rotated and flipped paths edit in place. Each drawing tool places one object, selects it and hands back to Select. Hovering any rail, toolbar or canvas icon shows its name, what it does and its shortcut.

### Node editing

Node editing (`src/path_edit.rs`, `src/ui/node_edit.rs`, `src/ui/toolbar/node.rs`) works like Illustrator's direct selection.

- **What can be edited.** Any shape outline: Pen and Pencil paths, the free shapes, the built-ins and imported SVGs. Opening a shape's nodes changes nothing; its first edit makes it a path that keeps its operation, colour, effects and place, and keeps its name in Layers (a Heart stays "Heart" unless renamed). One undo turns it back. Double-clicking text still edits its text (Convert to Paths gives its outlines nodes), and a component instance still opens its master. Groups, Flattened shapes and images cannot be node-edited.
- **Node kinds.** Every node is Straight (no handles, lines either side), Cusp (independent handles), Smooth (handles in line, own lengths) or Symmetric (in line, equal lengths). Dragging a handle obeys the kind: a Cusp handle moves alone, a Smooth node swings its other handle round keeping its length, a Symmetric node mirrors it. Kinds are saved with the path (`node_kinds` on `ShapeKind::Path`) and checked against the geometry on load; projects saved before kinds, imports and Combine results infer them from the handles.
- **Selecting.** Click a node, Shift-click to add or remove one, drag over empty canvas to select the nodes inside, Cmd+A for all. Selected nodes are filled; handles show for selected nodes and their neighbours. Dragging moves every selected node, arrows nudge them (Shift for 1 in steps).
- **Adding and removing.** Hovering a segment shows a ghost node; a click splits the segment there (de Casteljau, so the outline does not move). Delete, Backspace or Option-click removes nodes, refitting one cubic across the gap by least squares so the outline stays close. A path keeps at least two nodes, three when closed.
- **Node toolbar.** While editing, the edit toolbar becomes the node toolbar: Straight, Cusp, Smooth and Symmetric convert the selected nodes (the shared kind is lit, a mixed selection lights none; Straight to a curved kind adds Catmull-Rom handles), Add Node puts a node halfway between selected neighbours, Delete Node, Open Path splits a closed path at the selected node, Close Path joins the ends with a line, and Done (or Escape or Enter) finishes. Disabled buttons say why in their tooltip. Right-clicking a node offers the same actions.
- **Smoothing.** The Smoothing popover's strength slider (0 to 100) previews over the path. With nodes selected it recomputes their handles from their neighbours and makes them Smooth; with none it simplifies the whole path (Ramer-Douglas-Peucker at a tolerance up to 0.15 in) and refits Catmull-Rom curves, which tidies a jittery Pencil stroke. Apply is one undo step, as is every other node action.
- **Corners.** Node editing shows a small dot under a node that carries a live corner (see the Corner tool below), and leaves it alone through every kind change except Smooth or Symmetric, which have no sharp corner to round and so remove it.

### Corner tool

The Corner tool (`src/corners.rs`, `src/ui/corner_tool.rs`, `src/ui/toolbar/corner.rs`; key C) rounds, chamfers or scoops any corner of any path, the way Illustrator's Live Corners and Affinity's Corner tool do, and the rounding stays editable.

- **The model.** A `ShapeKind::Path` carries one live corner per node, `Corner { radius_in, style }` with style Round, Chamfer or Inverted, stored beside `node_kinds` and `#[serde(default)]` so older projects load with none. A corner leaves the node sharp and draws its shape every time the outline is evaluated (`corners::with_corners`): Round fits a circular arc tangent to both edges with the same cubic approximation the parametric shapes use, Chamfer cuts a straight line between the tangent points, and Inverted scoops a concave arc on the far side. The radius clamps to half the shorter adjacent edge, so adjacent corners never overlap, and the clamped value is reported for the read-out. Only the sharp nodes are stored; Offset, Combine, Warp, Make and export all see the one evaluated outline, so none of them change. A corner belongs to a Straight or Cusp node, and it travels with its node when nodes are added, removed or reordered.
- **The tool.** Select a path and its Straight and Cusp nodes each show a small circle widget. Drag one inward to round the corner, with the radius in the read-out; drag outward to reduce it; Option-click cycles Round, Chamfer and Inverted. A marquee selects nodes as node editing does, and dragging a widget with several selected rounds them all to the same radius. The edit toolbar shows a Radius field (an expression applying to the selected nodes), the three styles and Round all corners, which rounds every eligible node of the shape. Zero removes a corner. Each change is one `Edit::Corners` command and one undo step. A parametric shape (spec 49) hands its corner radii over as live corners when it becomes a path, so pressing A on a rounded rectangle gives a path with four Round corners of the same radius rather than baked arcs.

### Shape Builder and Knife

The tool rail adds Shape Builder (key Shift+M, Illustrator's key) and Knife (key K), the gesture-driven booleans that Combine and Slice do not offer (`src/geometry/planar.rs`, `src/knife.rs`, `src/ui/shape_builder.rs`, `src/ui/knife_tool.rs`).

- **Shape Builder.** With two or more shapes selected it computes the planar map of their evaluated outlines once per selection change (`geometry::planar_map`): every region bounded by the shapes' edges, tagged with which shapes cover it. The region under the pointer shows with a hatched accent fill. Dragging across regions unites them into one shape in the front-most input's colour and operation; a click on one region makes it its own shape; Option-drag or Option-click deletes regions. What is left of the inputs is split into shapes region by region, so it is a destructive operation like Expand, not a live group, and the map is rebuilt from the new selection after each step. Each release is one `Edit::BuildShape` and one undo step. Open paths, text and bitmaps take part through the outlines Kerf already flattens; single-line writing text has no area and is refused with the message Combine uses. The tool caps at eight shapes, so its tooltip says to select up to 8.
- **Knife.** Drag a freehand line, or Shift-drag a straight one, across the selected shapes, or across everything under the line when nothing is selected. On release every closed shape the line crosses splits into two or more shapes along it, each keeping the source's colour, operation and name with " 2", " 3" appended, and selected; an open path is cut at each crossing into separate open paths. A line that crosses nothing does nothing. The cut thickens the line to a hairline band and takes the booleans, so a cut edge lands within a thousandth of an inch of the line. Effects on the source are expanded first, since a live Offset cannot follow half a shape, and the pieces carry no effects. **Scissors** is the same tool with a click instead of a drag: click a point on a path's edge to open a closed path there, or cut an open one in two, snapping to nodes. Each cut is one `Edit::Knife` and one undo step.

## Text

The Text tool places a text object on click and opens it for typing, with its placeholder selected. Double-clicking a text with Select, or clicking one with the Text tool, edits its words in place: a multi-line editor sits over the text box on a 90 % white backdrop, in the UI face closest to the text's font at the zoomed size, and the canvas outlines follow each keystroke. Escape or a click outside commits, the whole session is one undo step, and a text left empty is removed (`src/ui/text_edit.rs`). While every selected object is text, a text group leads the edit toolbar: a Font dropdown (the bundled Kerf fonts, the writing fonts and every installed system font, described below), Size in points (1 to 1440, committed on Enter or when the field loses focus), a Style dropdown, an Alignment button that cycles left, centre and right, and Format. With several texts selected each control shows the shared value, or is blank where they differ, and a change applies to all of them. Format Text holds Letter Space (-200 to 1000) and Line Space (-500 to 2000), each a slider beside a number field; Text wrapping (No wrap or Wrap in box); Text Box Align (Top, Middle, Bottom, enabled only with Wrap in box); and Select Ungrouping. Letters replaces the text with one text per visible glyph and Lines with one text per line, each holding its own characters in the same font, style and size and placed exactly where it sat, curved letters turned to their tangent. The pieces share one Group, take the source's z position and are selected. Layers is disabled because no bundled font has layers, and warped text does not split (`src/text_ops.rs`). Wrap in box sets the wrap width to the current box width, and while text wraps, dragging a side handle moves the wrap width and reflows the words instead of stretching the letters. `ShapeKind::Text` outlines the string with `ttf-parser` into closed bezier contours in inch space, so text flows through `to_svg_path_d`, Combine, Offset, Contour and Make exactly like any path (TrueType quadratics are elevated to cubics). Text defaults to the Pen draw operation with its fill as `pathColor`, and can be switched to a cut operation to cut the letter outlines. Editing the string, font or size re-fits the object to its new natural size and keeps any resize scale and warp, so edited text does not snap back; move, resize, rotate, recolour, delete and undo work with the Select tool. A text object is grabbed anywhere inside its frame, not only on the letter outlines.

`src/text.rs` lays text out. The string may hold several lines, and each text object also stores a style (Regular, Medium, Bold, Italic, Bold Italic), letter and line spacing in thousandths of an em, left, centre or right alignment, an optional wrap width and a vertical alignment, all defaulting so older projects load unchanged. Glyph pairs are kerned from the font's GPOS pair adjustments, or its `kern` table when it has no GPOS. Inter uses its Medium and SemiBold faces for Medium and Bold; Space Grotesk sets its variable `wght` axis to 400, 500 or 700. No italic faces are bundled, so italics shear the outlines 12 degrees about the baseline. The text box is typographic rather than the ink bounds: its width is the widest line's advance (or the wrap width), and its height is the line count times the font's ascender to descender plus line gap, with the line spacing between lines. Typing a descender therefore never moves the box. Wrapping breaks at spaces, and a word wider than the wrap width keeps a line to itself. The layout keeps each glyph's line and character index, and its pen position and turn, and each line its text and origin, which is what splitting into letters and lines places from. The text toolbar edits the style, spacing, alignment and wrap.

**Text on a path.** Text runs along any curve, not only a circle (`src/text_path.rs`). Select one text and one shape and choose Text on path (Effects menu, command palette, Cmd+Option+T): the text takes its own copy of the shape's outline, the source stays (becoming a Guide unless it already cuts, so a word can run round the edge of a tag that is still cut) and the text is selected. The layout spaces each glyph along the path by its advance, sets its baseline centre on the curve by arc length and turns it to the tangent there; text longer than an open path overflows past the end on the tangent and wraps round a closed one. A text stores its path as `path`, its own contours in its local frame, defaulting to none so older projects load straight. The Curve panel becomes Path once a text is on one: it sets Side (Above or Below the path), Align along (Start, Centre or End), an Offset that slides the start along the path, and Remove from path, which straightens the text and keeps its size and font. Only a single unwrapped line follows a path; for other text the panel is disabled. Effects still offers Curve as a quick way to bend a line onto a circle: its Diameter slider and number field, in the current units, run from the smallest circle that fits the text to ten times its width, beside Text on top or Text below and Straighten. A text's circle is a signed diameter (0 straight, positive on top), and a circle made this way lays out the same as the matching circle path.

Text can use any font installed on the machine as well as the bundled ones. The Font menu opens with a search field, then "Kerf fonts" (Inter and Space Grotesk, both SIL OFL) and "System fonts" in alphabetical order. Typing filters both lists by family name, and Enter picks the first match. Each name is drawn in its own face once that face has loaded on a background thread; until then, and for very large font files, it uses the UI font. `src/system_fonts.rs` scans the installed fonts with `fontdb` once, on a background thread started with the app, so start-up never waits for it; until the scan finishes the menu shows "Loading fonts..." and text in a system font lays out in Inter. The scan leaves out hidden system families (names starting with a dot) and faces `ttf-parser` cannot outline, such as colour bitmap emoji. For a system family, each style resolves to the closest installed face by weight (400 or 700) and italic or oblique, read once and cached. A variable face sets its `wght` axis. A family with no bold face gets synthetic bold, which pushes every outline edge out by 1/48 em, and one with no italic face gets the same 12 degree shear as the bundled fonts. System text outlines, cuts, draws, saves and reloads exactly like bundled text. Projects save the font as a plain string: `"Inter"`, `"SpaceGrotesk"`, or the family name. A project naming a family that is not installed still loads. Its text renders in Inter, the file keeps the original family name, and the Font menu lists it in muted grey as "Name (missing)".

When a design names a system family that is not installed, the text cuts in Inter, and Kerf says so twice. Prepare shows a notice listing the families and saying their text cuts in Inter, with a Pick a font button that returns to the canvas with the first affected text selected, and Layers marks each such text with a warning glyph and a tooltip. `FontCatalogue::missing_for` answers it once the scan has landed, kept until the catalogue or the families in the design change, so asking every frame costs nothing (`src/system_fonts.rs`). Choosing an installed family clears both.

### Writing fonts

Writing fonts are single-line fonts: each letter is a few open strokes that a pen draws once, where an outline font makes the pen trace both sides of every stroke. The Font menu lists them under "Writing", between Kerf fonts and System fonts, each name drawn in its own strokes beside a small pen. The search covers them, and the "Writing only" chip hides every other section. The bundled families are Hershey Simplex Roman, Hershey Duplex Roman, Hershey Complex Script, Hershey Script Simplex and Hershey Gothic English, from the public-domain U.S. National Bureau of Standards data under the Usenet distribution notice in `assets/fonts/hershey/NOTICE`, and Relief SingleLine, under the SIL Open Font License 1.1 in `assets/fonts/relief-singleline/OFL.txt`. `assets/PROVENANCE.md` records where each came from and how it was converted.

Text in a writing font lays out with the same lines, alignment, spacing, wrapping and curve as any text, but its contours are open (`closed: false`), so `to_svg_path_d` writes no `Z`, the canvas draws them at the pen's nib width, and Make sends each stroke once. Glyphs keep reading order and each glyph keeps the font's stroke order; only stroke directions change, chosen so the pen travels least between strokes. The box runs from the font's ascender to its descender with no line gap. Style offers Regular and Italic (the shared 12 degree shear); Bold is greyed, because the pen size sets the line weight. Choosing a writing font for a text whose operation is Basic Cut, Wavy Cut or Perforate switches it to Pen in the same undo step, and a notice says "Writing fonts draw with a pen" with an Undo link that reverses both. Foil and the other draw operations are left alone, and choosing any other font never changes the operation. The command palette lists writing fonts too, with the same switch. Weld, Unite, Subtract, Intersect, Exclude, Slice, Offset and Sticker are disabled for a selection with single-line text ("Single-line text has no area to combine"); Attach works, so writing attached to a card draws on the card's mat. Effects > Convert to Paths turns text into a `ShapeKind::Path` with the same contours, open strokes staying open. Ungrouping to letters or lines, and Curve, keep the writing font.

Upload also takes an SVG font (`<font>` with `<glyph d="...">`). Kerf copies it to `fonts/` in the projects directory, registers it as `svg-<file name>`, says "Added writing font Name", and loads every font there on the next start; any other SVG imports as shapes, as before. Each path in an SVG font is a stroke. Many "single line" fonts fake strokes with zero-width closed outlines, which a pen would draw twice; a closed subpath whose two halves lie within 0.5 % of the em of each other collapses to its open centreline, so those fonts draw once too. `<hkern>` pairs kern the text. Projects save a writing font as `"stroke:<id>"`, for example `"stroke:hershey-simplex"`. A project naming a writing font that is not available loads, lays its text out in Hershey Simplex Roman, keeps the original id, and the Font menu lists it under Writing as "id (missing)".

`tools/stroke_font/` is the converter that made the bundled files: `cargo run --example stroke_font -- hershey <in.jhf> <out.json> --name "<Name>"` or `-- svg <in.svg> <out.json>`. It runs by hand, never at build time, so the app has one stroke format and the bundled fonts are reviewable JSON.

## Projects, Home and Settings

Projects are saved locally as JSON under the OS app-data directory (`~/Library/Application Support/Kerf/projects` on macOS), each with a PNG thumbnail rendered with tiny-skia. Kerf opens on the Home tab every time. The Home tab lists saved projects as cards with Edit and Make actions and a New Project card. The tabs from the last session wait in the tab strip above it, and clicking a tab or a card goes to the canvas. `kerf --open <project.json>` and `kerf --bench` skip Home and start on the canvas. File > Save writes the current canvas to its project, File > Home opens the Home tab, and File > Export... and File > Prepare for Design Space write files (see Export).

Work is never discarded, and nothing asks before leaving it: each open project remembers its design and title as last saved or opened, and its autosave keeps whatever differs (see Tabs and Autosave below). Save writes to a temp file and renames it over the old one, so a failed save leaves the previous version intact; the project keeps its identity and a banner at the top names the failure until dismissed. Import, export, open and delete failures use the same banner. A file Home cannot read (torn, hand-edited or from a newer Kerf) shows as a "Couldn't open" card that can be deleted, rather than vanishing. A project's id is its file name. Project JSON carries `format_version` (2 today): format 1 files upgrade on open, built-in shapes save by name, and an opened project or imported SVG goes through `Design::sanitise`, which reports any shape it dropped or resized. Thumbnails are read once when Home is listed and refresh after every save.

The View menu toggles magnetic snapping, inch or centimetre units, and a full or partial grid; the magnet button by the zoom pill is a shortcut for snapping.

### Autosave, versions and recovery

Work is saved continuously. Two seconds after the last change, and at least every 30 seconds while changes keep coming, the canvas is written to `autosave/<id>.json`. Nothing is written during a drag. The title bar's Save state beside the title reads "Saved", "Edited" or "Autosaved 10:42". Every canvas has a project id from the moment it opens, so a never-saved design autosaves too. It appears among Home's projects only once saved, but closing its tab keeps the work: Home lists an autosave with no project file and no open tab as a card marked "Unsaved" (newest first, before the projects) with **Open**, which offers Restore or Discard as any autosave does, and Delete, which asks first. An autosave that will not load shows as "Couldn't open" so it can be deleted, and one that is empty or untouched for 30 days is removed when Home's list is built (`store::unsaved`). Closing a clean blank tab leaves no card. All writes run on one saver thread, the only writer of the projects directory, so the UI never waits on the disk and no two writes race. Each write goes to a temporary file that is renamed into place, so a crash mid-write never leaves a torn file. A failed background write shows the error banner once until a write succeeds again.

A version is recorded on every Save (Saved), every 10 minutes of editing (Autosave) and before any Restore (Before restore). **File > Version history** opens a side panel listing versions newest first under day headings, each with its time, kind, thumbnail and name. Selecting one previews it read-only on the canvas. **Restore** makes it the design as one undo step. **Name** names a version and pins it. After each new version, pruning keeps every version from the last hour, the newest in each hour for the last day, the newest in each day for the last 30 days, and every Saved or pinned version from the last 90 days, at most 100 per project (`store::prune`, a pure function that changes nothing when run twice). Deleting a project deletes its versions and autosave too.

`session.json` names the open tabs in order, the active one and the running app's pid. Quitting asks nothing: closing the window writes every tab's pending autosave, then rewrites the session with no pid, and doing so twice changes nothing. At the next launch a clean session reopens its tabs in order with the same one active, in the strip above Home. A saved project opens from its file and, when its autosave is newer, offers "Restore" or "Discard" as its tab comes to the front; a never-saved project with an autosave opens blank and offers it the same way; a tab with neither is dropped. A pid that is no longer running means Kerf did not quit properly. A recovery dialog then lists each tab whose autosave is at least as new as its saved file, with its thumbnail and "Unsaved changes from 10:42": **Restore all**, **Restore selected** or **Discard**. Every chosen project reopens as a tab, in session order with the first active, each with its changes as one undo step over its saved file. Discard moves a saved project's autosave into its versions as an Autosave. Opening a project from Home whose autosave is newer than its file asks "Restore" or "Discard" in the same way.

### Tabs

Several projects can be open at once, each in its own tab with its own design, selection, undo history, view, tool and panels; Undo never crosses tabs. The tab strip above the top bar shows **Home**, then one chip per open project with its name, a violet dot while it has unsaved changes and a close button. It shows on Home always, and on the canvas and in the Make flow once two tabs are open, so a single project looks exactly as before. File > New and Cmd+T open a blank tab named Untitled-N with the lowest free N. Home's Edit and Make and the palette's projects open the project in a new tab, or show its tab when it is already open; an untouched blank tab gives way to it rather than piling up. Cmd+W closes the active tab (the close button closes any), Ctrl+Tab and Ctrl+Shift+Tab cycle and wrap, and Cmd+Option+1 to Cmd+Option+9 jump (Cmd+0, Cmd+1 and Cmd+2 are the zoom keys); the same commands are in the command palette. Closing a tab asks nothing: its pending autosave is written and offered when the project is next opened. Closing the last tab leaves a blank Untitled-1. Only the tab in front ticks autosave; a tab going to the background or closing writes its pending autosave at once. Deleting a project on Home closes its tab, and Clear all closes every tab with a saved project. There is one machine, so one Make runs at a time: Make in a tab while another tab's Make flow is open asks **Not now**, **Cancel that Make** (which cancels the device job, closes that flow and starts this one) or **Go to** that tab. Machine and device messages always reach the tab whose flow is open, whichever tab is in front. `src/ui/document.rs` holds one tab's state, `src/ui/tabs.rs` the tab operations and `src/ui/tab_bar.rs` draws the strip.

The projects directory holds:

```
<id>.json                        the saved project (unchanged format)
<id>.png                         its thumbnail
autosave/<id>.json               the latest unsaved state of an open project
versions/<id>/<unix ms>.json     one version, an ordinary project file
versions/<id>/<unix ms>.png      its 220 px thumbnail
versions/<id>/index.json         time, kind, name and pinned for each version
session.json                     the open tabs in order, the active one and the running app's pid
assets/                          the asset store (spec 28)
```

A directory from before autosave (flat `<id>.json` files only) lists and opens unchanged. `src/store/` owns the layout and every write: `mod.rs` (paths, atomic writes, versions, prune, delete, asset garbage collection), `autosave.rs` (the scheduler), `saver.rs` (the thread) and `session.rs` (the session file and recovery list).

### Units

One setting, inches or centimetres, drives every length the app shows or accepts: the rulers and grid, the inspector's X, Y, W and H, the Offset distance, the Project Preview mat size and the Prepare Material Size dropdown. Switch it from the View menu or the ruler corner and every surface follows on the next frame, guide positions included: the guide popover and the read-out beside a dragged guide show them in the current units. Designs always store inches, so typing 5.08 into W in centimetres makes a 2 in wide shape. Mat sizes carry metric names (`30.5 cm x 30.5 cm`); paper sizes such as A4 keep one name. The choice is saved to `settings.json` beside the projects directory and read at start-up.

`src/units.rs` is the only place a length becomes text. A unit test walks `src/` and fails if any other file (bar `machine.rs`, which holds the mat names) formats `in` or `cm` by hand.

The Shapes panel carries the 20 SVG presets plus around 50 procedurally generated shapes (defined in `shape_library.rs`), drawn from lines and cubic arcs and each scaled to 2 in on its long side. All but Heart, Equals and the procedural built-ins are placed as live parametric presets, so they stay editable after placing (see [Shape parameters](#shape-parameters)). Multi-contour shapes such as the ring, gear, paw print and frames exercise Contour, with each hole wound opposite its outline. A unit test checks every built-in is closed, never crosses itself or another of its contours, and fits its size; `cargo test --release --bin kerf shape_sheet -- --ignored` renders them all to `target/shape-sheet.png`. Its header holds a search field and a Filter button. Search keeps the shapes whose name contains the typed text, in any case. Filter opens a list of seven categories (Basic, Polygons, Stars and Bursts, Arrows, Frames and Outlines, Speech and Labels, Lines), each with its shape count. Turning on several shows shapes from any of them, and the button turns violet with a dot while any is on. A shape must match both the search and the categories. When nothing matches, the panel says so and offers Clear. Search and filters stay put when the panel is collapsed and reopened, but reset at launch. Each shape's category lives with its definition in `shape_library.rs`, and a unit test fails if one is missing. Every colour swatch (toolbar and each Layers row) opens a colour picker.

## Images

Upload (the rail's Upload, `AppCommand::Upload`) takes an SVG, PNG, JPG or WebP file. An SVG imports as editable shapes. An image opens the trace panel, which turns it into cut shapes or a Print Then Cut image. Whatever Apply makes is 100 pixels per inch, scaled down to fit 6 x 9 in, placed at the mat's top-left like an SVG, and selected; the whole Apply is one undo step. Phone photos stand upright, because the EXIF orientation is applied on import.

A Print Then Cut image is `ShapeKind::Bitmap`: the canvas and the mat previews draw the picture inside its cut line with Print Then Cut's faint shadow and thin cut line, and Make puts it on a Print Then Cut mat, prints its pixels on the print sheet and cuts its outline. Flattened with other shapes, it keeps its picture on the canvas, on the print sheet and in thumbnails. Home and version thumbnails draw the picture too, from copies at most 512 pixels on the long side that each run decodes once.

### The trace panel

The trace panel (`src/ui/trace_panel.rs`) takes the window until it applies or closes. On the left is the image, with a checkerboard where pixels are removed and the proposed cut lines drawn over it in the accent colour. Scroll to pan, pinch or Cmd-scroll to zoom, or use the zoom pill; Fit shows the whole image again. On the right are three steps, each collapsible and editable in any order:

- **Background.** Remove colour: click the image to remove the region of that colour. Tolerance (0 to 100) is a colour distance in CIE Lab, so it matches what the eye sees. Contiguous floods from the click; with it off, every pixel within tolerance goes. Auto remove floods from the border with the dominant border colour and a tolerance read from the border's spread. Stop at edges keeps a flood from crossing a strong Sobel edge, so a white subject on a white-ish background survives. Erase and Restore are brushes with a size slider. Every change is listed and can be removed on its own, and Undo (or Cmd+Z) takes back the last one.
- **Colours.** Threshold makes one black layer from the pixels darker than the slider (0 to 255), or lighter with Invert. Posterise finds 2 to 16 colours and shows them as swatches; clicking a swatch merges it into its nearest colour, and clicking it again brings it back.
- **Clean-up.** Speckle drops regions smaller than an area, shown in the current units. Smoothing (0 to 100) and Corner threshold (in degrees; a sharper join stays a corner) shape the fitted curves.

Output, under the steps, chooses what Apply makes:

- **Cut layers** (the default for Posterise): one Basic Cut shape per colour, filled with that colour, grouped. Layering picks **Stacked** (each layer includes everything above it, for layered cardstock) or **Side by side** (layers butt up without overlapping, for vinyl).
- **Single cut**: one Basic Cut shape. In Threshold mode it is the threshold layer; in Posterise it is the outline of everything kept.
- **Print Then Cut**: the cleaned image, with removed pixels transparent, stored as a new asset and placed as one Bitmap whose cut line is the outline of everything kept.

Every change re-traces a copy of the image 768 pixels on its long side, 50 ms after the last change, on the image worker; a small spinner shows while the preview is out of date. Apply traces a copy capped at 4096 pixels on the same worker, with a progress bar and Cancel, then adds the result through `Edit::Place`. Discard, or the close button, leaves without adding anything. The decoded image lives in the panel, never in the design, and is dropped when the panel closes.

Tracing is Kerf's own driver around `visioncortex` 0.8 (MIT OR Apache-2.0), the curve fitter behind vtracer: `src/trace/mod.rs` ports vtracer 0.6's outline fitting and adds its own Lab colour clustering, component labelling and per-colour masks, so Stacked layers nest and Side by side layers never overlap. Kerf does not depend on the `vtracer` crate itself, because vtracer 0.6 pulls in clap 2 and image 0.23 and fails `cargo deny check advisories`. Background removal and the brushes are pure functions in `src/trace/raster.rs`.

The image is decoded and stored on a worker thread (`src/trace/worker.rs`), so the window never stalls. Kerf reads the file's header first and refuses anything over 50 megapixels before decoding it, with an error naming the size ("the image is 7746 x 7746 pixels (60.0 megapixels)"); the decoder also runs under memory limits, so a file that lies about its size cannot allocate more.

Pixels never live in the design, which undo snapshots every frame. Each image is written once, as a PNG with its transparency kept, to `assets/<blake3 hash>.png` beside the projects (`src/assets.rs`); the shape keeps the hash. Uploading the same image again reuses the file. Projects that share an image share one file. At launch, before any upload, the image worker deletes the files no saved project, autosave or version uses; if any project file cannot be read it deletes nothing. A project whose image file is gone still opens, and the image shows as a grey hatched box labelled "Missing image". The canvas keeps the decoded images in memory and loads them on a background thread; a very large image is shown downscaled to 4096 pixels on its long side.

## Create AI

Create AI (spec 43) draws a cut-ready design from a sentence. The rail's Create AI item (the wand) opens its panel beside the rail, in place of the Shapes panel. Kerf is offline and has no account, so the user brings their own model: Claude, OpenAI or OpenRouter with their own API key, or a model served on their own machine. The model writes each design directly as SVG vector paths, which Kerf checks and imports. Kerf sends only the prompt, the style and the level of detail; never the design, a project name or a file.

**Create AI settings.** Everything a user needs to set up is in one window (`src/ui/create_ai_panel/settings.rs`), so nobody has to edit a file or set an environment variable. It opens from the panel's **Set up Create AI** button (shown while the chosen provider has no key), from the **Create AI settings** link under the panel, which also names the provider and model in use, and from the command palette (`AppCommand::AiSettings`). Escape, the close button and Done close it. It holds:

- **Provider**: Anthropic (Claude), OpenAI, OpenRouter or Local model (`ai::Service`), with a line on what each needs.
- **API key**, for the providers that need one: whether a key is saved or comes from the environment, a password field with Show key, **Save key**, **Remove key**, and a link to where to get one.
- **Server address**, for a local model, with the usual Ollama and LM Studio addresses.
- **Model**: a name field and **Load models**, which asks the provider for its models on a thread (`ai::Listing`, `Provider::models`) and lists them; typing filters the list, and a click picks one. OpenAI's list leaves out embedding, speech and image models, and OpenRouter's keeps only models that take a response format. A failed list says why, as a generation's error would ("Your API key was rejected."). **Use the default** puts the provider's default back.

Changes are saved as they are made: keys to the keychain, the rest to `settings.json`.

**Providers.** Each provider keeps its own model, saved under `ai` in `settings.json`:

| Provider | API | Default model | Key |
|---|---|---|---|
| Anthropic (Claude) | Messages API (`src/ai/anthropic.rs`) | `claude-opus-5-5` | `ANTHROPIC_API_KEY` or the keychain |
| OpenAI | Responses API (`src/ai/openai.rs`) | `gpt-6-astra` | `OPENAI_API_KEY` or the keychain |
| OpenRouter | Chat Completions (`src/ai/openai.rs`) | none: name one, such as `anthropic/claude-opus-5.5` | `OPENROUTER_API_KEY` or the keychain |
| Local model | Chat Completions on the Server address, by default Ollama's `http://localhost:11434/v1` (LM Studio uses `http://localhost:1234/v1`) | none: name the model the server has loaded | none |

`settings::default_ai_model` is the one place the default models are named. Generate stays disabled while the model name is empty. A local model has to follow the JSON schema well enough to be useful; small models often draw designs the validator rejects.

**Keys.** A provider that needs a key and has none shows, in the panel, what is sent and to whom, and the way into the settings window. Save key stores it in the OS keychain through the `keyring` crate (service `Kerf`, one account per provider, such as `anthropic-api-key` or `openai-api-key`): Keychain on macOS, Credential Manager on Windows, the kernel keyring on Linux, where it lasts until the user logs out. Keys never go into `settings.json`, a project or the debug log; the log redacts anything shaped like an API key (`sk-...`, which covers Anthropic, OpenAI and OpenRouter keys) or a bearer token before a line is written. A provider's environment variable wins over its saved key, and the settings window says so; nobody needs one. Remove key deletes the provider's key from the keychain.

**Generating.** The panel takes a prompt of up to 400 characters, a **Style** and a **Detail**:

| Style | What the model draws |
|---|---|
| Silhouette | A solid shape in one piece. |
| Line art | Outlines drawn as filled bands, never thinner than the minimum feature size. |
| Stencil | Every hole bridged to the outside, so no island of film falls out. |
| Sticker | A solid design with an even offset border. |

| Detail | Smallest piece at 4 inches wide | Paths | Path nodes |
|---|---|---|---|
| Simple | 0.25 inches | 8 | 600 |
| Medium | 0.15 inches | 20 | 1500 |
| Detailed | 0.08 inches | 40 | 3000 |

Generate asks for four candidates. While the model draws, four grey tiles breathe and Cancel stands by; the window never blocks, because the request runs on its own thread (`ai::Job`). Cancel drops the job, and an answer that still arrives goes nowhere. The results show as four tiles; click one to select it. **Insert** adds it at the centre of the view, 4 inches wide, as one black Basic Cut shape named from its title (for example "Dinosaur skateboard"), in one undo step (`Edit::Insert(Insert::Generated)`). **More like this** asks for four variations of the selected design. **Regenerate** runs the prompt again. Errors never clear the prompt: a refusal shows "Kerf couldn't make this:" and the model's explanation, a 401 "Your API key was rejected.", a 429, 503 or 529 a retry message with the `retry-after` time, and a network failure "Kerf couldn't reach" and the provider ("Anthropic", "OpenAI", "OpenRouter" or "your local model server").

**History.** Every cut-ready design is saved to `ai/<id>.json` beside the projects (`src/ai/history.rs`, written atomically through `store`), with its prompt, style, detail, time and SVG. The panel's History tab lists them with thumbnails, newest first; clicking one inserts it, with no network needed.

**The requests.** Every provider gets the same system prompt (`src/ai/prompt.md`, built in), the same conversation and the same JSON schema of `candidates` and `decline`, from `src/ai/wire.rs`, over raw HTTPS with `ureq` and rustls. Every request streams, so a long reply never hits a timeout; connecting and the start of the response each have 120 seconds (300 for a local server, which may load the model first), and the whole call has ten minutes. Kerf reads how a reply ended before its content: a refusal shows its explanation, and a reply cut off at the output limit is reported as unreadable.

- **Anthropic.** `POST /v1/messages` with structured outputs (`output_config.format`), adaptive thinking at `output_config.effort: "medium"`, and server-side fallback (`fallbacks: "default"` under the `server-side-fallback-2026-07-01` beta) so a policy decline is retried on the model Anthropic recommends for it. On `stop_reason: "refusal"` the panel shows `stop_details.explanation`.
- **OpenAI.** `POST /v1/responses` with `text.format` set to the strict JSON schema and `store: false`, so OpenAI keeps no copy. A refusal arrives as refusal text; `response.incomplete` with `content_filter` is a refusal too.
- **OpenRouter and local servers.** `POST /chat/completions` with `response_format` set to the strict JSON schema; on OpenRouter, `provider.require_parameters` sends the request only to hosts that honour it. A local server that ignores the schema may wrap the JSON in prose or a code fence; Kerf takes the outermost `{...}`, and the validator judges the result as usual.

**Validation.** Model output is untrusted. `src/ai/validate.rs` is pure, and every candidate passes through it before a tile shows. It screens the raw XML before any SVG parser runs (so an `<image href>` is never read from disk): text, images, scripts, external references, gradients, patterns, clip paths, masks and a DOCTYPE are refused, as are files over 256 KB or 5000 elements. It then imports the SVG with `shape_library::import_svg`, rejects stroke-only paths, checks the path and node budgets, welds every fill into one outline 4 inches wide, drops pieces smaller than the detail's minimum (rejecting the design if they were more than 5 % of its area), and for Stencil rejects any enclosed hole. A design that fails is asked for once more, in a follow-up message that quotes the reasons; if it fails again its tile says "This one didn't come out cut-ready" and why. The other tiles are unaffected.

**Tests.** No test touches the network or the keychain: under `cfg(test)` the panel uses `FakeProvider` (canned SVGs from `src/ai/fixtures/`) and an in-memory key store, and the keychain code is not compiled into tests. `src/ui/tests_spec43.rs` covers generating, inserting and undoing, refusals and key errors, Cancel with a late answer, history across a restart, switching providers, a local model, the settings window and its model list, and a key-leak check that saves Anthropic and OpenAI keys through the window and greps the settings, the debug log and every file written.

## Export

File > Export..., the top bar's Export button and Cmd+E open one dialog. It offers:

- **Format.** SVG; DXF (ASCII R12 polylines and arcs) for laser software; PDF (vector, one page per mat); or PNG and JPEG, a picture of the design for a listing, a message or a forum.
- **Scope.** The whole design, on a sheet of its bounds plus 0.25 in, at its canvas positions; or one file per mat, laid out as `composition::compose` packs it, so a mat's file matches the Project Preview and Prepare. PDF is always one page per mat.
- **Style.** Filled (closed shapes filled, and Pen, Score, Deboss, Engrave and Foil drawn as 0.01 in strokes) or Outlines (every contour a 0.001 in hairline, for laser software). DXF is always outlines. Style is hidden for PNG and JPEG, which always draw as the canvas does.
- **Units.** Inches or millimetres, following the units setting. SVG writes `width` and `height` in the unit over a `viewBox` in points, so it opens at true scale. DXF writes its coordinates in the unit with Y up from the bottom left and sets `$INSUNITS`; the dialog says which unit, because strict R12 readers ignore it.
- **Mirror.** Off unless ticked, for Iron-On.

PNG and JPEG add their own options under Format. **Resolution** is 72, 150, 300 or 600 dpi (default 300), with the pixel size shown live as you change it. **Background** is Transparent (PNG only, the default), White or the Mat colour with its grid and rulers off. **Margin** is an expression field in the chosen units, default 0.25 in as SVG uses. JPEG adds a **Quality** from 60 to 100 (default 90) and has no transparent option. **Show as made** draws cut outlines only, which is what a listing of a cut file usually wants. The raster is drawn with tiny-skia in the same per-operation styles as the canvas, so a Score line is dashed, a cut fills its colour and a Print Then Cut image shows its pixels from the full-size decode, matching the Project Preview. An export over 100 megapixels is refused in the dialog with the size it would be (a 600 dpi 24 x 24 in mat is 207 megapixels), so lower the resolution or export one mat at a time.

The dialog lists the files it will write and their sizes. Export asks for a file name for one file, or a folder for several. Hidden shapes, hidden contours and Guide shapes are left out, as Make leaves them out; with nothing left, Export is disabled.

In Filled style, SVG and PDF export draw an image's pixels inside its cut line: the SVG embeds a PNG data URI clipped by the outline, and the PDF an image with a soft mask, both at up to 300 dpi at the placed size. Outlines style and DXF export the cut line only. The dialog says which applies when the design holds an image. The writers stay pure: the app decodes the images a file needs when it is written and passes them in. An image whose file is gone exports as its filled cut line, and a flattened image exports its outline.

Every format keeps each shape's operation. Each (operation, shape) pair is a layer named `"{operation} - {shape}"` (`Score - Heart`, `Pen - Text`) in the shape's colour, or its pen's colour for Pen, where `{shape}` is the name the layer shows in Layers, so a renamed layer exports as `Pen - Speech Bubble`. A repeated name gets ` 2`, ` 3`. The members of an Attach link sit in a group named after the link when it has a name, else `Attached - {cut shape}`, and a container's children in a group named after the container. SVG writes each layer and group as an Inkscape layer (`<g inkscape:groupmode="layer">`); DXF as a `LAYER` entry with an R12-safe name (`Score-Heart`) and the nearest AutoCAD colour, with cubics fitted by arcs within 0.001 in and a full circle written as one `CIRCLE`; PDF as an optional content group, so Acrobat and Illustrator list the operations as layers. `export::sheets` decides every name, colour and position once, and the three writers only change coordinate space, so the formats cannot disagree.

### Prepare for Design Space

File > Prepare for Design Space asks for a folder and writes one filled SVG per mat, named `"{project} - Mat 1 - Black - Basic Cut.svg"` (mat number, material colour, operations), plus `README - Design Space.txt`. The SVGs state their size in inches over a `viewBox` in points at 72 per inch whatever the units setting, because Design Space's upload hands the file to a server converter whose unit handling cannot be read from the client (`docs/evidence-webapp.md`, "SVG upload"). They carry no `clipPath` or `pattern`, which the upload rejects. The guide explains how to upload each file, that every layer arrives as Basic Cut, and how to set each back: it lists each file's layers with their colours ("Score - Heart, #d0202e"), since layer names may not survive the upload, and says which cut layer to Attach each to. It also asks for a check against the mat's ruler before Make. Nothing here talks to Design Space or Cricut's servers; Kerf only writes files.

## Identity

Kerf is a flat, monolithic editor: white panels separated by 1px low-contrast borders, a light void behind a floating white artboard, and one violet accent. The palette lives in `src/ui/tokens.rs` as the single source: `bg_panel #FFFFFF`, `bg_canvas_void #F1F3F5`, `bg_artboard #FFFFFF`, `border_subtle #E9ECEF`, `text_primary #212329`, `text_muted #6C757D`, `accent_primary #7048E8` and `accent_hover #F3F0FF`, with `ON_PRIMARY` white for text on the accent. Layout: a 40 px top bar, a 48 px tool rail, a 240 px inspector (Properties over Layers, with Properties shown only while something is selected), and the artboard sized to the active mat (12 x 12 in by default). Fonts are Inter and Inter Display (SIL OFL).

Hover help is a white card beside the control with a small arrow pointing at it, shown after the pointer rests for half a second: rail items open it to the right, controls in the lower half of the window open it above, and everything else below. It gives the control's name, one line on what it does and its shortcut. Icons Kerf draws itself (the Combine, Align, Effects, Group, Attach, text-format and lock icons) are original 1.5 px line drawings in `icons.rs`; `tests/snapshots/01-icons.png` shows them all at 20, 24 and 48 px and is compared on every run.

The snapshot tests render with wgpu. `reference-1-blank.png` and `reference-2-shapes.png` are written to `target/snapshots/` at 1750 x 1096, the CSS size of the two reference screenshots, for a person to lay beside them; the compared baselines live in `tests/snapshots/`.

Inter and Inter Display under `assets/fonts/` are the body and heading fonts, from the rsms/inter release under the SIL Open Font License (`assets/fonts/OFL.txt`). The canvas chrome keeps only the local actions: New and Shapes on the rail, the machine chip, Save, Preview and Make. It has no subscription, account, cloud or marketing surfaces.

### Projects directory

Projects live under the OS app-data directory. Set `KERF_PROJECTS_DIR` to use another one; `settings.json` sits beside it, and uploaded images live in its `assets/` folder. The app receives its directory as a value, and every test uses its own `tempfile` directory, so tests never read or write the real settings.

## Benchmark

One heavy design, 150 top-level objects and about 440 Layers rows covering every feature, stresses the editor. `src/bench.rs` builds it from a seed; `kerf --bench-generate <dir>` writes it as `heavy.kerf.json` and a whole-design `heavy.svg`. `kerf --open <project.json>` opens any project file in a tab.

`kerf --bench <project.json> --bench-out <metrics.json>` opens the design, plays a fixed script through the app's own commands (idle, drags, zoom, select all, undo, Make Prepare, cut preview) with vsync off, writes per-phase frame times and quits; `kerf --bench-report` turns those metrics and a process-sample file into a table, appended to `bench-results/<date>.json` (ignored by git). Frame times are milliseconds, and under 16.7 ms is 60 Hz. `cargo test --release heavy_design -- --ignored --nocapture` is the headless gate with ceilings on idle, drag, load and Make entry (spec 38), which CI runs on macOS.

## Platforms and releases

Kerf builds and runs on macOS, Windows and Linux. CI (`.github/workflows/ci.yml`) runs format, clippy, the tests and the advisory check on all three, on every pull request, on GitHub-hosted runners. [CI](ci.md) explains what runs and how releases are built. The kittests render through wgpu: Metal on macOS, the WARP software adapter through DX12 on Windows, and Mesa's lavapipe Vulkan driver under `xvfb-run` on Linux. The Linux build needs the packages in `tools/release/linux-deps.txt`; CI and the release job both install them from that file.

The places that differ by platform:

- **Shortcuts.** Every shortcut label goes through egui's `format_shortcut`, so it reads ⌘ on macOS and Ctrl elsewhere. A test fails if a string literal under `src/ui/` spells out the macOS key.
- **System fonts.** `system_fonts.rs` scans the macOS font folders, `%WINDIR%\Fonts` and `%LOCALAPPDATA%\Microsoft\Windows\Fonts` on Windows, and the fontconfig folders on Linux (`/usr/share/fonts`, `/usr/local/share/fonts`, `~/.local/share/fonts`).
- **Serial ports.** Open cutters list ports by the names the system gives them: `/dev/cu.*` on macOS, `COM3` on Windows, `/dev/ttyUSB0` or `/dev/ttyACM0` on Linux. A profile saved with a port this machine does not have loads and shows "Port not found".
- **Windows console.** Release builds use the Windows GUI subsystem, so no console window opens with the app. The command-line modes (`--version`, `--bench`, `--bench-generate` and the report commands) attach to the parent terminal first, so their output still appears.

`kerf --version` prints `kerf <version> (<commit>)` and exits before any window opens. `build.rs` stamps the commit, and on Windows also embeds the icon and version details into `kerf.exe`.

### Icons

`tools/release/icon.svg` is the one source. `cargo run --example icons` (`tools/release/icons.rs`) renders it with resvg into `tools/release/icons/`: `Kerf.icns` for macOS, a multi-size `kerf.ico` for Windows, and `kerf-<size>.png` from 16 to 512 px for Linux. The generated files are committed, so packaging needs no image tools. Run it again after changing the SVG.

### Packaging

Each platform has one script, which the release job runs and which works the same on a developer's machine. Each writes its artefacts to `target/dist/`.

- `tools/release/package-macos.sh <version>` builds `Kerf.app` for both architectures, joined with `lipo`, and `Kerf-<version>-macos-universal.dmg`, signed ad hoc. `--app-only` builds just the app, for this Mac's architecture. `--sign` is the second phase, which signs, notarises and staples the built app (see `docs/ci.md`).
- `tools/release/package-windows.ps1 <version> -Target <triple>` builds `Kerf-<version>-windows-<arch>.zip` (portable) and `.msi`, with `cargo wix` from `tools/release/wix/main.wxs`. The installer is per user, adds a Start menu shortcut, and has a fixed upgrade code, so a newer `.msi` replaces an older one. `-Sign` is the second phase, which signs `kerf.exe`, rebuilds the packages around it and signs the `.msi` (see `docs/ci.md`).
- `tools/release/package-linux.sh <version>` builds `Kerf-<version>-linux-<arch>.deb` with `cargo deb` (metadata in `Cargo.toml`), `.AppImage` with linuxdeploy, and `.tar.gz`, for this machine's architecture.

`tools/macos/bundle.sh` calls `package-macos.sh --app-only` and installs the result to `/Applications`, or to the folder given as its first argument.

### Releasing

1. `tools/release/bump.sh <version>` sets the version in `Cargo.toml` and `Cargo.lock`. It does not commit, tag or push.
2. Commit, then push the tag it prints, `v<version>`. Writing the version's `CHANGELOG.md` section is welcome but optional: the release still ships, and its notes list the merged pull requests.
3. `.github/workflows/release.yml` checks that the tag is `v` plus `Cargo.toml`'s version, and fails at once if not. It then builds the eleven artefacts on five runners (macOS universal, Windows x64 and arm64, and Linux x86_64 and aarch64 on Ubuntu 22.04, so the glibc floor stays low) and runs `kerf --version` from each one.
4. Further jobs install the `.msi`, check its Start menu shortcut and upgrade it with a higher version, and install the `.deb` and start the app and the AppImage on Ubuntu 22.04 and 24.04.
5. The last job writes `SHA256SUMS` and creates a draft GitHub Release whose notes are the tag's changelog section when there is one, and the merged pull requests when there is not. Review the draft and publish it by hand.

Signing happens only when its secrets exist: `MACOS_CERT_P12`, `MACOS_CERT_PASSWORD`, `APPLE_ID`, `APPLE_TEAM_ID` and `APPLE_APP_PASSWORD` for Developer ID signing and notarisation on macOS, and `WINDOWS_CERT_PFX` and `WINDOWS_CERT_PASSWORD` for Authenticode on Windows. Without them the macOS app is signed ad hoc, the Windows files are unsigned, and the release notes list the unsigned artefacts and how to open them.

Run the workflow by hand (Actions, Release, Run workflow) for a dry run: the same builds and checks, with the artefacts, `SHA256SUMS` and notes kept as the run's `release-dry-run` artifact instead of a release. Its `tag` input checks a given tag instead, to test the version check. GitHub offers Run workflow only once `release.yml` is on the default branch.
